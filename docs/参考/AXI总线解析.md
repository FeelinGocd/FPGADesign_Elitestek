# AXI4 总线解析（速查）

> 用途：本工程用 AXI4-Full 接 DDR3（CPU / 显示取数 / 加速器读写四路汇聚）。
> 这份只留"写 RTL 和排查问题时真正会用到"的部分 —— **本工程怎么接、有哪些硬限制，在 `../spec/设计总纲.md` §8**。
> 原始的长篇协议笔记（612 行）已随 spec 整理一并归档。

---

## 1. 五通道 / 两种事务

| 事务 | 通道 | 说明 |
|---|---|---|
| **写** | **AW**（写地址）+ **W**（写数据）+ **B**（写响应） | 三条通道，缺一不可 |
| **读** | **AR**（读地址）+ **R**（读数据，`RRESP` 跟着数据每拍回来） | 两条通道，**读没有独立的响应通道** |

| 通道 | 关键信号 |
|---|---|
| AW | `AWID / AWADDR / AWLEN / AWSIZE / AWBURST / AWVALID / AWREADY` |
| W | `WDATA / WSTRB / WLAST / WVALID / WREADY` |
| B | `BID / BRESP / BVALID / BREADY` |
| AR | `ARID / ARADDR / ARLEN / ARSIZE / ARBURST / ARVALID / ARREADY` |
| R | `RID / RDATA / RRESP / RLAST / RVALID / RREADY` |

---

## 2. 握手规则（AXI 正确性的全部核心）

1. **VALID 不许等 READY**，也**不许由 READY 组合出来**（不能出现 `VALID = f(READY)` 的组合环）；
2. **VALID 拉高后 payload 必须保持不变**，直到握手完成；
3. READY 拉低只是**背压**，等多久都合法 —— AXI 里**没有** AHB 的 RETRY / SPLIT；
4. 地址通道与数据通道**分离**，可以不同拍；**每通道各自背压**，这正是 AXI 能并发多笔事务的原因；
5. **主机必须消费 B**（否则从机写响应队列满 ⇒ 整条写通道被堵死）。

## 3. 编码速查

| 编码 | 含义 |
|---|---|
| `AxBURST` | `00` FIXED / `01` INCR（最常用）/ `10` WRAP |
| `AxSIZE` | `2^SIZE` 字节/拍（`SIZE=4` ⇒ 16 字节/拍 = 128 bit） |
| `AxLEN` | 突发**拍数 − 1**（0~255 ⇒ 最多 256 拍） |
| `AxLOCK` | 0 普通 / 1 独占（互斥访问） |
| `BRESP/RRESP` | `00` OKAY / `01` EXOKAY / `10` **SLVERR**（从设备错误）/ `11` **DECERR**（地址无映射） |

**地址推进**（INCR）：第 n 拍的地址 = 起始地址 + `n × 2^SIZE`。

**两条必须遵守的边界规则**

1. **一笔突发不得跨 4 KB 边界**（协议硬规矩，从机行为未定义）；
2. 起始地址应按 `2^SIZE` 对齐（不对齐时从机按对齐后的地址走，靠 `WSTRB` 表达真实偏移）。

---

## 4. ID 与顺序

- **同 ID 保序、跨 ID 可乱序**；ID 是**响应归属**的依据；
- **读写通道之间没有任何顺序约束** —— 读可以插在两笔写中间。"先写后读"必须靠软件 / 硬件显式同步；
- 多主场景：AXI4 **没有共享总线**，第二个主一出现，**互联就是必需的**；互联按 burst 粒度分时放行到同一个从设备
  （**宏观并行、微观串行**）。

---

## 5. 与 APB / AHB 的对照（最容易记岔的地方）

| APB / AHB 里的概念 | AXI4 里的对应物 |
|---|---|
| PSEL / PENABLE 两相 | 无相位，只有每通道 VALID/READY |
| HREADY（全局拖拍） | 各通道**独立** READY |
| HTANS / 地址相 | AW / AR 与 W / R **分离** |
| HBURST（固定 4/8/16） | `AxLEN` + `AxSIZE` + `AxBURST`，长度可变（≤256 拍） |
| HRESP = RETRY / SPLIT | **不存在**，用背压代替 |
| HRESP = ERROR | `BRESP/RRESP` = SLVERR / DECERR |
| 事务严格按序 | 同 ID 保序、跨 ID 可乱序 |

**常见理解偏差**

| 容易记成 | 正确说法 |
|---|---|
| "AXI 有 3 种事务" | **2 种事务、5 条通道**（B 是写事务的第三步，不是独立事务） |
| "W 数据发完写就完成了" | 必须**等到 B**，且主机必须消费 B |
| "读也有独立响应通道" | 没有，`RRESP` 跟数据每拍回来，用 `RLAST` 收尾 |
| "多主可以同时读写同一个外设" | 访问**不同**从设备才真并行；同一个从设备仍按 burst 分时 |
| "有了 AXI4 就能多主，MUX 是可选的" | 互联是**必需的** |
| "AXI4-Full 就是拿来访问寄存器的" | Full 面向**内存类**从设备；低速寄存器走 APB 或 AXI4-Lite |
| "READY 不给就是出错" | READY 拉低只是背压 |
| "先写后读总线会保证顺序" | 读**写通道之间没有任何顺序约束** |

## 6. 写主机自检清单

- [ ] VALID 不是由 READY 组合产生的？拉高后 payload 保持不变？
- [ ] LEN / SIZE / BURST 与实际数据量一致？`WLAST/RLAST` 与 LEN 严格对应？
- [ ] 地址在 4 KB 边界内？按 SIZE 对齐（或显式用 WSTRB 表达偏移）？
- [ ] 交出 AW 之后**一定**把这一笔的 `WLAST` 交出来？（本工程踩过：漏了会锁死整条 AXI）
- [ ] `BRESP/RRESP` 被消费？非 OKAY 时有恢复策略？
- [ ] 发 DDR 请求前已等 `cal_done`？地址 < 256 MB？
