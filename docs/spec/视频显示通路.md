# 视频显示通路（lineBuffer）：实现逻辑

> 状态：已实现，仿真 + 上板均已验证（2026-09-21）

## 1. 解决什么问题

DDR 里放几块帧缓存，**FPGA 自己把像素取出来送到 HDMI**，CPU 只负责写寄存器
（定基址 / 开使能 / 交帧 / 看帧率）。整套通路跨两个时钟域：

| 时钟 | 频率 | 干什么 |
|---|---|---|
| `clk` | 100 MHz（user_clk） | APB 寄存器、handler、控制器取数、PingPong 写侧、AXI4 主口 |
| `clk_HDMI_x1` | 148.5 MHz | PingPong 读侧、拆包、HDMI 时序、TMDS |

## 2. 数据流

```
DDR 帧缓存
   │  AXI4 读突发（≤256 拍、不跨 4KB）
   ▼
AXI4_Master ──► bufferControler（按行取，一行 360 拍）
                     │ 写口
                     ▼
            async_PingPongBuffer（双 bank，跨 100M ↔ 148.5M）
                     │ 读口
                     ▼
            bufferUnpacker（16 字节/拍 → 3 字节/像素）
                     │ 24bit 像素
                     ▼
            HDMI_Top（1080p60 时序 + TMDS 编码）──► 显示器
```

## 3. 模块分工（越界就是 bug 的来源）

| 模块 | 职责 | **不**管什么 |
|---|---|---|
| `APB0_lineBuffer` | APB 解析 + 12 个寄存器 | 不含任何功能逻辑 |
| `bufferAPBHandler` | 寄存器 → 有效信号：翻页索引、模式锁存、DONE 消费、帧率统计 | 不碰取数 |
| `bufferControler` | 按 `{段0,段1}` 把一行搬进 PingPong，一行交一块 | **不知道**双缓冲 / DONE / 翻页 |
| `async_PingPongBuffer` | 双 bank 跨域，四相握手，读侧决定何时换块 | — |
| `bufferUnpacker` | 128bit/拍 → 24bit/像素 | — |
| `HDMI_Top` | 1080p60 时序 + TMDS | — |
| `AXI4_Master` | AXI 读命令与数据 | — |

## 4. 寄存器表（APB0 槽 1，绝对地址 = 0xF8101000 + 偏移）

| 偏移 | 名字 | 读写 | 说明 |
|---|---|---|---|
| 0x1000 | ID | RO | 恒 `0x4C423031`（"LB01"），用来确认 APB 通路 |
| 0x1004 | FRAMEA_BASE_ACC | RW | 缓冲 A·左半（分屏时加速器画的） |
| 0x1008 | FRAMEA_BASE_CPU | RW | 缓冲 A·右半（分屏时 CPU 画的） |
| 0x100C | FRAMEB_BASE_ACC | RW | 缓冲 B·左半 |
| 0x1010 | FRAMEB_BASE_CPU | RW | 缓冲 B·右半 |
| 0x1014 | FRAMEC_FULL | RW | 全屏 C（上电默认显示） |
| 0x1018 | FRAMED_FULL | RW | 全屏 D |
| 0x101C | STATUS | RW | bit0 = ENABLE（不锁存，写 0 立即停）<br>bit1 = SPLIT（帧边界才生效） |
| 0x1020 | FPS_ACC | RO | 加速器侧帧率（交帧事件/秒） |
| 0x1024 | FPS_CPU | RO | CPU 侧帧率 |
| 0x1028 | DONE_CPU | W1S | 写 1 置位（CPU 交帧） |
| 0x102C | DONE_ACC | W1S | 写 1 置位（加速器交帧，也可由硬件脉冲置位） |

★ 基址寄存器必须 16 字节对齐，不对齐的写会被**直接丢掉**（读回还是旧值，软件据此能发现写错）。

## 5. 帧缓存格式（软件最容易写错的地方）

| 项 | 全屏 | 分屏半幅 |
|---|---|---|
| 宽 × 高 | 1920 × 1080 | 960 × 1080 |
| 每像素 | 3 字节 | 3 字节 |
| **行距** | **5760 字节**（无 padding） | **2880 字节**（无 padding） |
| 一块大小 | 6,220,800 B（≈5.93 MB） | 3,110,400 B（≈2.97 MB） |

★ **一个像素的字节顺序是 B、G、R** —— 地址最低的那个字节是蓝。
（RTL 依据：`bufferUnpacker` 把最早到的字节放在 `pixel_data[7:0]`；
TMDS 编码器把 `[23:16]` 当红、`[15:8]` 绿、`[7:0]` 蓝。）

红蓝反了、或者整屏斜条纹，基本都是这里写错了。

## 6. 一行为什么必须拆笔

一行 360 拍 > AXI 单笔上限 256 拍，且一笔不得跨 4KB 边界。
行首在 4KB 页内的偏移逐行漂移（5760 mod 4096 = 1664，32 行一个循环）：

| 页内偏移 | 拆法 |
|---|---|
| 0 | 256 + 104（2 笔） |
| 1664 | 152 + 208（2 笔） |
| 3328 | **48 + 256 + 56（3 笔）** ← 不是固定 2 笔 |

拆笔规则写成函数 `burst_of()`：`n = min(256, 到 4KB 线的拍数, 本段剩余拍数)`。
**本笔拍数在命令期间必须锁存**（AXI 要求命令期间稳定）。

全模块没有乘法器/除法器：行距和字节数是左移 4 位，到 4KB 线是右移 4 位。

## 7. 双缓冲与翻页（DONE 的规矩）

- **写 DONE = "这一块画完了，下一个帧边界切过去显示"**
- 置位：软件 W1S 写 1，或加速器硬件脉冲
- **清零：只有 handler 在帧边界翻页之后自己做，软件不许清**
- 左右两路独立：`DONE_ACC` 翻左半（全屏时翻 C↔D），`DONE_CPU` 翻右半
- 谁先画完谁先翻，另一路继续显示它原来那块
- **写 SPLIT 的那一拍，两个 DONE 一起丢掉**（它们属于旧模式）
- 索引只在帧边界翻，模式（SPLIT）也只在帧边界锁存 → 一帧之内的取数几何永远一致
- **索引跨模式保留**：全屏翻到 D 之后切分屏，左半显示的是 B·左半

## 8. 帧对齐：与加速器的握手

**显示 → 加速器：`lineBuffer_frame_start`**（写域单拍）

跨域做法：读域的帧起始脉冲（6.73ns 宽）先转成 toggle，再在写域做 2 级同步 +
"已消费"比对，产生单拍事件。
★ 不能直接拿读域脉冲过 2FF —— 写域 10ns 才采一次，约 1/3 的帧会被整帧漏掉。

**约定（加速器侧必须遵守）**：

1. 收到 `lineBuffer_frame_start` 之后**才开始写后台缓冲** —— 那一刻显示已经切走，
   读写不会碰同一块；
2. 一帧画完（或一块画完）才拉 `acc_frame_done` 单拍脉冲。

**控制器侧的对应规则**：

- 开机没收到 `frame_start` 之前不取数；
- **只有"使能着的那个帧边界"才允许开始取数**（见第 10 节第 3 条）；
- 取完第 1079 行就**帧尾停手**，等下一个帧边界才取新帧第 0 行
  （提前取会取到旧帧内容 —— 那一刻基址还没翻）。停手不花代价：帧边界到第一个
  有效行有 41 行 ≈ 607µs，取一行只要 ~5µs。

## 9. 帧率统计

"帧率" = **每秒发生了几次交帧事件**（DONE 的 0→1），不是显示刷新率。

- 时间基准借显示场起始：数满 60 个 `frame_start` 算一秒（1080p60）；
- 每个窗口边界把上一窗口的计数锁存进 `FPS_ACC / FPS_CPU`；
- **所以只交一次帧的话，那个 1 只在一个窗口里存在**，之后回到 0 —— 这是正常语义，
  不是故障（读的时候建议轮询取峰值）。

## 10. 上板踩过的四个坑（都已修 + 补了回归）

| # | 现象 | 根因 | 怎么发现的 |
|---|---|---|---|
| 1 | 块被截成 257 拍 | 一笔的拍数是组合值，命令期间会变 | 控制器 TB |
| 2 | 翻页后仍显示旧内容 | 帧边界**同拍竞争**：handler 翻索引、控制器同拍锁基址 | 整链 TB |
| 3 | 整屏每行水平错开 | **帧中间写 ENABLE** 就立刻取数，读者在"一行的中间"开始消费 | **上板** |
| 4 | 翻页完全不发生 | `DONE_ACC` **缺软件 W1S 写通路**（文档写了、代码没实现） | **上板** |

第 3 条的解法：只有"使能着的帧边界"才允许取数；使能一撤就撤销许可。
第 4 条的解法：把软件写 0x202C 并进交帧事件（和 CPU 那一路对称）。

## 13. 还没做的

- **加速器接入**：APB 槽 2（0x2000~0x2FFF）+ AXI `Axi_Mux` 的 S2（已留空接常量），与 lineBuffer 的 槽1/S1 同号规则一致

  真正的压力要等加速器（它能写几百 MB/s）。
  账先算好：全屏 60fps 的"写 372 + 读 373 ≈ **745 MB/s**"，占 DDR3 有效带宽的 ~75%。
