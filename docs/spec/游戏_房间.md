## 1. 数据模型

7×7 网格，一格一间房；起点固定 **(3,3)**。房间 id = `y * 7 + x`。

```
room_t { type, gx, gy, owner, w, h, layout, flags, reward, flip }
```

| 字段 | 说明 |
|---|---|
| `type` | ROOM_NONE / START / EMPTY / ITEM / SHOP / BOSS |
| `owner` | `-1` = 自己就是锚点；`>= 0` = 这是多格房的**覆盖格**，指回锚点 |
| `w / h` | 只对锚点有意义：普通房 1×1，L 和 Boss 是 2×2 |
| `flip` | 异形房镜像方向（bit0 左右、bit1 上下）；普通房恒 0 |

**多格房 = 一条锚点记录 + 若干覆盖格**。覆盖格的 `type` 也写同一个类型，但 `owner` 指回锚点，
判邻居 / BFS / 连通性都先过 `room_canon()` 折算成锚点。

三种形状：

| 形状 | 占格 | 锚点位置 | 地形 |
|---|---|---|---|
| 1×1 | 1 | 自己 | `g_maps[]` 参数化生成（40×23） |
| L | 2×2 缺一格 | **行优先第一格**（不一定是左上角） | `LAY_map_L`（45×35 逐格表） |
| Boss 2×2 | 4 | 左上角 | `LAY_room_2x2`（45×35 逐格表） |

> ★ 特殊房（道具 / 商店 / Boss）**只能是 1×1**：挑特殊房时跳过 `w > 1 || h > 1`。

## 2. 生成规则

一层 = 最多 **100 轮**尝试，全失败才用兜底十字图（`room_fallback()`）。

每轮：

1. 起点 (3,3) 先占住；
2. 生长循环（`room_try_generate()`，guard 4000）：
   - 随机挑一间已有房 + 随机方向；
   - **同方向只有 25% 概率接受**（继续拉直走廊要抽签）⇒ 多拐弯、少长走廊；
   - 每步 **1/3 概率优先摆 L 房**（占 3 格），4 种摆法一次试完，都不行才退回 1×1；
   - **不许成环**：新格子 4 邻域里只能有 1 间已有房（整张房间图是一棵树）；
   - 格数到 `stage_cells() = 16 + 2×(stage-1)`（封顶 24）就停；
3. 挑特殊房（`room_try_specials()`）：道具 / 商店 / Boss 各 1，
   **必须是叶子**（只接 1 间普通房）、两两 8 邻域不相邻、Boss 放最远叶子且不贴起点；
4. `game_room_validate()` 复查（起点/道具/商店/Boss 各 1、成树、连通、Boss 不贴起点）。

> ★ `l_left > 0` 时整轮**判失败重来**（每层必须有 1 间 L）。
> ★ 兜底十字图**没有 L 房** —— 真触发兜底的那一层看不到 L。

### 2.1 L 的落子规则

`room_place_L(c00, flip)`：

- 2×2 的 4 格里，`flip` 决定**缺口**是哪一格，其余 3 格是房间；
- 缺口格本身要空着（这就是"L"），但**不占住它**：以后在这格里长出一间独立小房间是允许的；
- 3 格对外必须**正好碰到 1 间房**：
  - `> 1` ⇒ 把两间已有房连通了（成环）；
  - `= 0` ⇒ 谁也不挨着，成了孤岛（缺口正好是"刚长出来的那格"时会这样）。

### 2.2 实测分布（Python 模型，2000 局）

| 形状 | 缺口左下 | 缺口右下 | 缺口左上 | 缺口右上 |
|---|---|---|---|---|
| 占比 | 24.9% | **3.9%** | 37.7% | 33.6% |

> ★ 分布**不均匀**：能摆成哪种，取决于 2×2 块周围的已有房间（缺口左下 / 右下对邻居方向更挑）。
> 要均匀得改成"先判可行、再从可行集合里随机挑"，代价是多一段代码，目前没做。

## 3. 异形房地形（一张图 + 镜像）

`map_L` 只有**一份** 45×35 地形（`LT_map_L` 1,610 B + `RT_map_L` 1,575 B = 3,185 B）。
4 种形状**不存 4 份**，读数时按 `flip` 翻镜像 —— **额外数据 0 字节**。

### 3.1 镜像轴是"内容外接框"，不是画布

```
x' = s_mx - x      s_mx = 内容 xmin + xmax   （map_L = 6+34 = 40）
y' = s_my - y      s_my = 内容 ymin + ymax   （map_L = 5+29 = 34）
```

> ★ 用画布中心（44 / 34）去翻，整间房会**平移 4 格跑到竞技场外面**——因为内容只占 x6..34，不在画布正中。

### 3.2 三个读法分工（★ 别混）

| 函数 | 答什么问题 | 镜像怎么改 |
|---|---|---|
| `game_world_tile_at()` | 这一格是什么字符 | 翻坐标；角块 `C/X/Y/Z` 按 `k ^ flip` 换 |
| `game_world_rot_at()` | **贴图怎么转** | 翻一个方向 ⇒ `1↔3`；两个都翻（180°）⇒ `0↔2` 也换 |
| `game_world_dir_at()` | 这一格**朝哪一边**（门用） | 左右翻 `1↔3`；上下翻 `0↔2` |

> ★ **"朝向"和"贴图角度"不是一回事**：上下翻的时候，一扇朝下的门变成朝上（朝向 2→0），
> 但贴图只转 180°（角度还是 2）。混用会让门指到错的那一格。

### 3.3 场地

| | |
|---|---|
| 画布 | 45×35 格 |
| 竞技场（可走矩形） | x 8..32、y 7..27 |
| 世界像素 | 1440×1120（比屏幕大 ⇒ 相机跟随） |

## 4. 门

| | |
|---|---|
| 数量 | `map_L` 里 **8 个 'D'**，正好等于 `MAX_ROOM_DOORS = 8`（每条 `door_info_t` 28 B） |
| 占格 | **两格**：一个 `D` + 相邻一格 `.`（编辑器约定，贴图 40×64 正好盖住） |
| 归属格 | 把房间外接框等分成画布，看"门朝房间内那格"落在哪个格子；**只有压在接缝上的门才允许借格** |
| 触发 | **门格 `D` 本身**（1×1）；人站在门槛里才算走门 |
| 进门落点 | 门内侧一格（`place_at_door`），不会站进墙里 |
| 贴图 | 40×64，按**朝向**画；两边各探进墙 4 px |

> ★ **第二格的方向不是固定的**：原图里它在 `D` 的 `+x`（横门）/ `+y`（竖门），**镜像后翻到 `-x` / `-y`**。
>   贴图位置、补墙格、黑洞判定三处都必须用 `door_pair_sx/sy()` 算，写死 `+1` 就会"门整体挪一格 + 墙上一个黑方块"。
> ★ `MAX_ROOM_DOORS = 8` 已经被占满：以后在图上画第 9 扇门会被**静默丢掉**（画成墙）。
> ★ 自检：一间房 8 扇门**全都没邻居**时串口打 `ROOM: all doors walled (room N)` —— 那是 bug，不是正常情况。

## 5. 可走性 / 碰撞

- **撞墙只看脚底那一行**（`game_player.c`）：身体可以探进 2 格厚的墙带；
- 逐格判定 `game_room_cell_walkable()`：`B` / `K` 可走，**门洞两格**（`D` + 门内侧）可走，其余挡；
- L 的缺口、墙带、画布黑边都靠这条挡住（不需要专门写"缺口碰撞"）。

## 6. 小地图

- 底板 7×7 = **82 px**（10 px 格 + 2 px 缝），右上角固定；
- **一间房画一次**：外接框占满 ⇒ 整块矩形；没占满（L）⇒ 逐格 + 只补**同房间相邻**的缝（缺口那侧一个像素都不碰）；
- 连接线只在**两间都是 1×1** 之间画（多格房的内部缝不画灰点）；
- 当前房间白块**最后画**：1×1 = 4×4、占满 2×2 = 8×8、L = 6×6（画在离质心最近那格）。

> ★ L 的缺口里长出独立小房间时，图上就是"L + 一个小方块"，**不合并成 2×2**——这是正常表现，不要改。

## 8. 踩过的坑（别改回去）

1. **锚点被挑成特殊房** ⇒ 整间变 2×2。挑特殊房跳过 `w>1||h>1`。
2. **门后没挖穿**：`map_L.json` 的 (14,7)、(24,22) 曾是 `W`，进门会被墙卡住。现在改 `B`，`mapfmt.py` 有校验。
3. **小地图内部缝画连接线** ⇒ L 中间多一个灰点。缝只补同房间的。
4. **"脚底判定"在房间上方不生效**：夹取也只看脚底，别用整个碰撞盒先挡住。
5. **`#ifdef LAY_map_L` 散在 6 处** ⇒ 布局改名会静默关掉 L 生成。现在收敛成一个 `HAS_L_ROOM`。
6. **外接框不能省**：锚点不一定在左上角（缺口左上时在右上）。曾经"简化"成 `锚点 + 偏移` 时把赋值一起删了
   ⇒ 8 扇门全算到 (0,0) ⇒ **门全部变成墙**（2026-10-24 上板抓到）。
7. **门洞第二格方向不固定**：镜像后会翻到 `-x`/`-y`。写死 `+1` ⇒ 门挪一格 + 墙上一个黑块。
8. **L 的 3 格必须正好碰 1 间房**：`>1` 成环，`=0` 成孤岛（缺口正好是刚长出来那格时会发生）。
9. **`map_1x1` 已改名 `map_1x1_type0`**：`g_kinds[]` 里的宏要一起改。

## 10. 与隐藏房的关系

隐藏房的完整设计在 `交接_2026-10-24.md` §4（本版**未实现**）。和房间系统交叉的只有四条：

1. **不参与房间图**：成环 / 连通 / 叶子 / 格数都不算它；靠"在 `game_room_validate()` 之后才放"保证
   （若哪天把 validate 挪到后面，必须在 `room_has_cycle()` 和连通性 BFS 里跳过 `ROOM_HIDDEN`）。
2. **候选 = 所有空格**（4 邻域无 Boss），**平均概率**挑一个；挨 1 间房也算合法。
3. **缺口格可以长隐藏房**（缺口现在不占住了）—— 就是"L 的豁口里藏着一间屋子"。
4. **门渲染只认正常房**：目标是隐藏房时 `is_door()` 返回 0，邻居那侧画成木墙；`target` 仍保留给炸弹/开门用。
