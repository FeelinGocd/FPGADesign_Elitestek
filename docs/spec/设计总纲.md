## 0. 一句话

CPU 跑游戏逻辑、发绘图命令；加速器把矩形画进**后台**帧缓冲；画完整帧交帧，显示通路在**帧边界**翻页。

最终画面 **1280×720@60** 由 FPGA 自己从 DDR 取数上屏，CPU 只写寄存器。

## 1. 系统分层与数据流

### 1.1 分层

| 层 | 内容 |
|---|---|
| **L1 软件**（RISC-V） | 游戏逻辑、命令生成、双缓冲与交帧、脏区、自检 |
| **L2 总线** | APB3（控制面）+ AXI4（数据面）+ `Axi_Mux` 四路汇聚 |
| **L3 加速** | GPU_2D：命令域 / 访存域 / 像素域 / 同步配置域 |
| **L4 存储** | 片上 BRAM（素材、调色板、命令 FIFO、行缓冲）→ DDR3（帧缓冲、素材）→ SPI Flash（开机装载） |
| **L5 显示** | lineBuffer：DDR 取数 → 跨域双 bank → 拆包 → 720p60 TMDS |

### 1.2 目标链路

```
      ┌────────── CPU（软件，100 MHz）──────────┐
      │ 1. 跑游戏逻辑(位置/碰撞/动画)            │
      │ 2. 生成绘图命令                          │
      │    cfu_type_R(...) ── 自定义指令 CI ──┐   │
      └──────────────────────────────────────┼───┘
                                             │ CFU 端口（8 根线）
      ┌──────────────────────────────────────▼───┐
      │            加速器 GPU_2D                  │
      │  命令 FIFO → 命令解析 → 逐行推进           │
      │      ↓ 源①DDR 读 / 源②片上 PRAM / 填充色   │
      │  合成器（选路 + 逐像素 alpha 混合）         │
      │      ↓ 打包（96b→128b）→ 写控制器          │
      │  写回 → 后台帧缓冲（AXI S3）               │
      └──────┬──────────────────────┬────────────┘
             │ AXI 读 (S2)          │ acc_frame_done（单拍）
      ┌──────▼──────────────────────▼────────────┐
      │ lineBuffer：frame_start → 帧边界翻页 →     │
      │             取数 → 拆包 → TMDS → HDMI      │
      └──────────────────────────────────────────┘
```




| 面 | 走什么 | 位置 |
|---|---|---|
| **命令面** | 自定义指令 CI（`cpu0_customInstruction_*`） | 不占地址空间 |
| **配置 / 状态面** | APB 寄存器 + C 驱动 | APB 槽 2 = `0xF8102000` |
| **数据面** | AXI4 主口 | `Axi_Mux` **S2 = 读 / S3 = 写**（显示取数走 S1） |

> **赛题两句话各管一件事，别读串**：
> "解析 RISC-V **发送**的渲染指令" ⇒ 约束的是**命令从 CPU 直接发过来**，形态没规定 ⇒ 我们用 **CI**；
> "C 驱动**配置寄存器**" ⇒ 约束的是**驱动要写寄存器**，没说绘图命令必须走寄存器 ⇒ 我们用 **APB 槽 2**。
> 赛题全文里"**自定义**"出现 **0 次**，两条路都合规。

## 2. 加速器的四个域

**边界原则：A 只跟 CPU 打交道，B 只跟 DDR，C 只跟像素，D 只跟"帧"和"配置"。跨域直接连线是 bug 的温床。**

| 域 | 块 | 职责 |
|---|---|---|
| **A 命令域** | `CmdChannel`（CI 从端 + 译码 + 命令 FIFO）、`CmdExec` | 收 CI（**收到就回 rsp**）、两条 CI 拼一条命令、取命令 → 按 `op` 分派 → 逐行推进 → 判收工 |
| **B 访存域** | `pixel/DDR/DDRSource`、`pixel/DDR/DDRUnpacker`、`factory/DDRPacker`、`factory/WriteController`、`interface/AXIMastersHandler` | 逐行起址 + 拆 4KB 笔；读回来拆像素；96b→128b 打包；发写 + WSTRB 遮头遮尾 |
| **C 像素域** | `pixel/palette/*`（PRAM + 调色板查表）、`process/colorKey`、`process/alphaBlending`、`factory/Compositor` | 取样 → 查表 → 选路 → 逐像素混合 → 出 96b 像素流 |
| **D 同步与配置域** | `interface/GPU2D_APBHandler`、`GPU_2D` 顶层的行模式锁存、调色板 / 素材 RAM | 帧同步（`frame_start` / `acc_frame_done`）、寄存器、片上素材 |

### 2.1 时钟域

| 时钟 | 频率 | 谁用 |
|---|---|---|
| `user_clk` | 100 MHz | 命令侧 + 加速器 + 显示通道的写域（顶层 `clk_ci` / `clk_acc` 都接它） |
| `clk_HDMI_x1` | **74.25 MHz**（720p60；TMDS 串行时钟为其 5 倍） | 显示通道读域：PingPong 读侧 / 拆包 / HDMI 时序 / `frame_start` 的产生 |

> ★ `clk_ci` 与 `clk_acc` 现在**同源** —— `CmdChannel` 里那一级同步今天不是真跨域；
> 名字留着是为了将来分频，**别误以为 CDC 已经验过**。

### 2.2 三级复位（顺序不能乱）

| 复位 | 来源 | 谁吃 |
|---|---|---|
| `sys_rst` | `pll_locked & user_pll_locked`（异步断言、同步撤销） | APB 寄存器格子（`APB0_gpu2d`） |
| `axi_rst_n` | `sys_rst & cal_done_d2`（DDR 校准完成才放行） | `rst_ci_n` / `rst_acc_n`：命令侧 + 加速器 |
| `lineBuffer_rst_n` | `axi_rst_n & pll_HDMI_locked` | `rst_hdmi_n`：**只给显示通道** |

1. 寄存器格子用 `sys_rst`，比 `axi_rst_n` **早放行** —— CPU 可以在 DDR 校准完成前就写基址 / 使能。这是板上验过的行为，**不能顺手统一成 `axi_rst_n`**。
2. `rst_hdmi_n` 比 `rst_acc_n` **晚放行**（多串一个 HDMI PLL 锁定），它只该管显示通道。
3. 显示通道内部还有一层像素域复位同步（`asyn_rst_syn`）。

### 2.3 跨域点（只有三处）

| 跨域点 | 方向 | 怎么做 |
|---|---|---|
| 命令 FIFO | CI 侧 → 命令侧 | `async_fifo`（**216 位**命令 + 格雷码指针，512 深 ≈ 13.5 KB） |
| PingPong | 写域 → 像素域 | 两个异步 FIFO + BlockRAM，读侧决定何时换块 |
| `frame_start` | 像素域 → 写域 | 读域 toggle → 写域 2FF + 边沿比较，出**单拍**（不能直接拿读域脉冲过 2FF：写域 10 ns 才采一次，约 1/3 的帧会整帧漏掉） |

### 2.4 ★★ 行模式有两份锁存，复位域不同 —— 这是故意的，不许合并

- 显示通道那份：`GPU2D_APBHandler` 里，复位 `rst_n_disp = rst_hdmi_n`
- 加速器那份：`GPU_2D` 里的 `lineBuffer_mode_r`，复位 `rst_acc_n`

两份都在 `lineBuffer_frame_start` 那一拍锁存同一个 `split_pending`，所以永远同步切换。

**加速器那份绝不能挂 `rst_hdmi_n`**：HDMI PLL 锁定位一旦把它摁住，加速器就按错误几何算地址，
命令收发卡死 —— CI 是**阻塞握手**的，CPU 停在那条指令上，VexRiscv 的调试模块就再也停不住它
（OpenOCD 报 `Assertion failed: target->state == TARGET_HALTED, vexriscv.c:1351`），
表现成"整块板子没法调试"。**回退即好、装回即坏**，定位花了很久。

## 3. 总线与地址映射

### 3.1 SoC 概览

- CPU：**VexRiscv RV32IM + Zicsr + Zifence**，单核；无 A/C/F/D 扩展，**无 MMU**、无用户态。
- ICache / DCache：**4 KB × 1 way × 64 B/line**。
- CLINT = 100 MHz；**SoC 内部不含 DDR3 控制器** —— DDR 是外接 AXI4 从口。

### 3.2 外设与总线

VexRiscv 原生总线是 **BMB**，SoC 用桥分成两条：

| 总线 | 用途 | 挂载 |
|---|---|---|
| **APB3**（`0xf8000000` 起 16 MB） | 低速 / 控制面 | UART0 / SPI0 / GPIO0 / I2C0 / **用户 APBSlave0**（`0xf8100000`，64 KB） |
| **AXI4** | 高带宽数据面 | DDR（`io_ddrA`）、用户 AXI 主窗（`0xe1000000`，本工程未接）、外部加速器主口 `io_ddrMasters_0` |
| **直连 BMB** | — | 片上 RAM（`0xf9000000`，4 KB）、PLIC、CLINT |

已启用的低速外设：UART0 `0xf8010000`（115200 8N1）/ SPI0 `0xf8014000`（接 Flash）/ GPIO0 `0xf8015000` / I2C0 `0xf8016000`。
未启用：UART1/2、SPI1/2、I2C1/2、GPIO1、FPU、APBSlave1–4、USER_TIMER、WDT0、AXIMaster_1。

### 3.3 地址映射总表

| 区 | 地址 | 说明 |
|---|---|---|
| **DDR3（主存 + 帧缓冲）** | `0x0000_1000` 起 | 声明 `0xe000_0000`，受 28 位地址限制，**实际 256 MB** |
| AXI_A 用户主窗 | `0xe100_0000`（16 MB） | 本工程未接 |
| UART0 / SPI0 / GPIO0 / I2C0 | `0xf8010000` / `0xf8014000` / `0xf8015000` / `0xf8016000` | |
| 用户 APB3（APBSlave0） | `0xf810_0000`（64 KB） | 自建外设区 |
| CLINT / PLIC | `0xf8b00000` / `0xf8c00000` | |
| 片上 RAM | `0xf900_0000`（4 KB） | bootloader |

**用户 APBSlave0 槽分配**

| 槽 | 绝对地址 | 外设 |
|---|---|---|
| 0 | `0xf8100000` | 按键 KEY |
| 1 | `0xf8101000` | **空**（原 DDR 自检 checker，已摘除；访问它返回 `PSLVERROR=1`） |
| 2 | `0xf8102000` | **GPU_2D 一整块**（与 AXI S2/S3 同号）：`0x2000`–`0x2018` 加速器观测、`0x2040` 起显示通道；子块位 = `PADDR[6]` |
| 3~15 | `0xf8103000` 起 | 扩展预留 |

### 3.4 中断（PLIC）

| ID | 来源 |
|---|---|
| 1 / 4 / 8 | UART0 / SPI0 / I2C0 |
| 12 / 13 | GPIO0 |
| **16** | **userInterruptA**（`frame_start` → 当作帧中断用） |
| 30 | system_axi_a |

### 3.5 加速器怎么接进来

| 你的东西 | 挂哪条总线 | 地址 / 方式 |
|---|---|---|
| 命令 / 状态 / 配置寄存器 | **APB3** | `0xf8102000` 起（槽 2） |
| 帧缓冲读写（数据面） | **AXI4 主口** | `Axi_Mux` **S2 读 / S3 写**；显示取数走 **S1** |
| 完成信号 | 硬件脉冲 | `acc_frame_done` → 并入 `DONE_ACC` |

## 4. DDR3 分区与帧缓冲布局

### 4.1 三条硬约束

| # | 约束 | 后果 |
|---|---|---|
| 1 | **所有 DDR 地址必须 < `0x1000_0000`（256 MB）** | `Axi_Mux` 32 位 → DDR3 从口 28 位，高 4 位被丢弃，超出会回卷 |
| 2 | **一笔 AXI 突发不得跨 4 KB 边界** | AXI4 协议硬规矩 |
| 3 | **CPU 写完的内存，在别人读它之前必须刷 D-cache** | CPU 有 4 KB 1-way D-cache，别的设备看不见它 |

### 4.2 分区表

| 区域 | 起始 | 结束 | 大小 | 写者 | 读者 |
|---|---|---|---|---|---|
| 保留空洞 | `0x0000_0000` | `0x0000_0FFF` | 4 KB | — | — |
| **CPU 程序 / 数据 / 栈** | `0x0000_1000` | `0x0001_FFFF` | 124 KB（链接脚本锁定） | CPU | CPU |
| **命令队列**（v1 未用，留档） | `0x0002_0000` | `0x0002_FFFF` | 64 KB | CPU | 加速器 |
| **堆 / 栈扩展** | `0x0003_0000` | `0x001F_FFFF` | 1.81 MB | CPU | CPU |
| **Framebuffer A** | `0x0020_0000` | `0x007F_FFFF` | **6 MB** | 加速器 / CPU | 显示读出器 |
| **Framebuffer B** | `0x0080_0000` | `0x00DF_FFFF` | **6 MB** | 加速器 / CPU | 显示读出器 |
| **分屏对比备用帧**（2 帧） | `0x00E0_0000` | `0x019F_FFFF` | **12 MB** | 左半 CPU / 右半加速器 | 各自读出 |
| **素材区**（唯一可变区） | `0x01A0_0000` | DDR 顶端 | 上限 ~230 MB | CPU（开机从 Flash 装） | 加速器 / CPU |

固定占用约 26 MB（10%）。**容量不是瓶颈，瓶颈在 §6 的带宽。**

> ★ **素材区是唯一会变大的区域**，所以放在最后 —— 以后加素材只改 Flash 的烧录内容，这张表一个字不用动。
> ★ 当前 demo 实际用的 A/B（全屏 C/D）两块缓冲落在 `0x0800_0000` 起，地址由**软件**传给显示寄存器，硬件不写死。

### 4.3 帧缓冲布局（720p 可见，RGB888）

**可见 1280×720，但物理行跨距沿用 1080p 的 5760 字节**（每行只用前 3840 字节，后 640 个像素的空间空着不读不写）。
好处是**换分辨率没动帧缓冲布局、也没动 GPU 的行跨距**；代价只是多占 1.35 MB 地址空间（不产生带宽）。

| 项 | 全屏 | 分屏半幅 |
|---|---|---|
| 宽 × 高（可见） | 1280 × 720 | 640 × 720 |
| 每行**读多少字节** | 3840（= 1280 × 3） | 1920 |
| 每行**下一行跳多远**（行距） | **5760** | **2880** |
| 每行拍数（显示读） | 240 | 120 |
| 一帧实际用到 | 5760 × 720 = 4.15 MB | 2.07 MB |

> ★ 显示侧把这四件事**分开处理**：可见宽度（1280）／本行读取长度（`DISPLAY_LINE_BYTES = 3840`）／
> 下一行步进（`DISPLAY_ROW_STRIDE = 5760`）／GPU 写入行跨距（`LINE_BYTES = 5760`）。
> 混成两个数就是当初「整屏每行水平错开」那个坑。改分辨率的完整清单见 `_归档/分辨率调整_1280x720.md`。

三个整除条件同时成立：

| 性质 | 是否满足 | 说明 |
|---|---|---|
| 被 16（128 bit = 一拍）整除 | ✅ 5760 = 16 × **360** | 一行正好 360 拍 |
| 被 3（1 像素）整除 | ✅ 5760 = 3 × 1920 | 行首永远是像素 0 |
| 行首拍相位 / 像素相位 | ✅ 恒为 0 | 每行都从一拍的开头、字节 0 开始 |
| 内存浪费 | ✅ 0 | 跨距 = 行宽，整帧是一整块连续数组 |

```
第 y 行第 x 个像素 = 帧缓冲基址 + y × 行距 + x × 3
第 y 行第 n 拍     = 帧缓冲基址 + y × 行距 + n × 16        (n = 0..239)
```

> **代价**：行首不是 4 KB 整数倍，4 KB 边界在行内的位置逐行漂移（5760 mod 4096 = 1664，32 行一个循环）
> ⇒ 每行最多 3 笔突发。若强行对齐 4 KB，跨距要补到 8192，**每行浪费 2432 字节（+42%）** —— 不值得。
> ★ **一个像素的字节序是 B、G、R**（地址最低的字节是蓝）。红蓝反了、整屏斜条纹，基本都是这里写错。

### 4.4 缓存一致性

CPU 写帧缓冲后，像素停在 D-cache 里没落到 DDR，屏幕从 DDR 读 ⇒ 看不到。
**方向要记对：不是"谁读到旧数据"，而是"CPU 写的像素根本没到 DDR"。**

| # | 场合 | 时机 |
|---|---|---|
| 1 | CPU 写 Framebuffer | 翻页（换 front 指针）之前 |
| 2 | CPU 装载贴图 / 素材 | 启动加速器之前 |
| 3 | CPU 写命令队列（v1 不走这条） | 写"启动"寄存器之前 |

函数：`data_cache_invalidate_all()`（`.word(0x500F)`，VexRiscv 自定义指令，**实际带写回**）。

## 5. 存储分层

| 层 | 器件 | 容量 | 掉电 |
|---|---|---|---|
| **L1** 片上 BRAM | Ti60F225 内置 | **256 块 × 10 Kbit = 320 KB** | 丢 |
| **L2** 片上小 RAM | SoC 内部 | bootloader 4 KB + OCR 8 KB | 丢 |
| **L3** DDR3 | 板载 x16 | **256 MB**（28 位地址封顶） | 丢 |
| **L4** SPI Flash | GD25LQ64 | **8 MB** | **保存** |

> ⚠️ 常见笔误：板载 Flash 是 **8 MB**（GD25LQ64 的 64 是 **64 Mbit**），不是 64 KB。

### 5.1 各层的性格

| 层 | 带宽 | 随机访问 | 定位 |
|---|---|---|---|
| **BRAM** | 极高（多端口） | ✅ 单周期 | **小而热**：调色板、素材、命令 FIFO、行缓冲 |
| **DDR3** | 实际 **1.0~1.2 GB/s（读写共享）** | ⚠️ 几十拍延迟 | **大而冷**：帧缓冲、大图 |
| **Flash** | 串行，几十 MB/s | ❌ 要发命令 + 地址 + dummy | **只做仓库，开机搬一次** |

### 5.2 Flash 布局（实测定稿）

| 段 | 起始 | 长度 | 烧录文件 |
|---|---|---|---|
| bitstream | `0x000000` | 实测 1.90 MB（按 3.5 MB 预留） | `project.bit` |
| app | `0x380000` | **固定 124 KB** | `project.hex` |

**素材起点为什么不会漂移**：bootloader 从 `0x0038_0000` 搬**固定 124 KB**到 DDR `0x0000_1000`，
拷贝长度写死 ⇒ app 的 Flash 占用是定长 ⇒ C 代码写到多大，素材起点都是 `0x3C0000`。

```
上电 → bootloader：SPI 初始化 → 读 Flash 0x380000 的 124 KB → DDR 0x1000 → 跳 userMain
```

> 素材**不走 Flash**：它们以 BRAM 初值的形式烧进 bitstream（见 §5.3），所以运行期完全不碰 Flash。

### 5.3 素材放哪：两条路线

| 形态 | 怎么来 | 代价 |
|---|---|---|
| **片上 PRAM（唯一路线）** | 8bpp 索引 + 调色板（一项 `AARRGGBB`），由 `assets.hex` / `palette.hex` 在**生成 bit 阶段**烧进 BRAM | **零装载时间、零 DDR 读**；换素材要重新综合 + 重编固件 |

**为什么值得走片上路线**（带宽账，全屏 BLIT）：

| 源从哪来 | 每帧流量 | 帧率 @920 MB/s |
|---|---|---|
| RGB888 源（DDR 读） | 读 6.22 + 写 6.22 + 显示 6.22 = 18.66 MB | 44 FPS ✗ |
| 索引源放 DDR | 2.07 + 6.22 + 6.22 = 14.5 MB | 63 FPS |
| **索引源放片上（现方案）** | **写 6.22 + 显示 6.22 = 12.44 MB** | **74 FPS** ✓ |

⇒ "整屏拷贝"是唯一打不到 60 FPS 的场景，把源搬到片上之后它退化成"只写"。

## 6. 带宽预算（本工程真正的瓶颈）

### 6.1 两侧理论带宽恰好配平

| 侧 | 算法 | 结果 |
|---|---|---|
| AXI 侧 | 128 bit × 100 MHz | 1.6 GB/s |
| DDR3 侧 | x16 × 800 MT/s（tCK 2500 ps） | 1.6 GB/s |

> ⚠️ **DDR 颗粒只有一条 DQ 总线，读写不能同时进行** ⇒ 1.6 GB/s 是**读写共享**的总量。
> 实际可用按 65~75% 估：**约 1.0~1.2 GB/s**。

### 6.2 显示读出需求（RGB888）

| | 640×480@60 | 1280×720@60（现用） | 1920×1080@60（历史） |
|---|---|---|---|
| 每行字节 / 拍数 | 1920 B / 120 拍 | 3840 B / **240 拍** | 5760 B / 360 拍 |
| 行周期 | 31.78 µs | 22.22 µs | 14.81 µs |
| **读出速率** | 55 MB/s | **166 MB/s** | 373 MB/s |
| 占理论 1.6 GB/s | 3.5% | **10.4%** | 23.3% |
| 占实际 1.0 GB/s | 5.5% | **16.6%** | 37% |

⇒ 720p 下显示只占读通道不到 **1/6**，余量非常宽。

### 6.3 并发预算（1280×720，加速器画半屏）

| 流量 | MB/s |
|---|---|
| 显示读（整帧） | 166 |
| CPU 写半屏 / 加速器写半屏 | 83 / 83 |
| 加速器读贴图（**有复用**） | ~10 |
| 加速器读贴图（**无复用**，逐像素 1:1） | ~110 |
| **合计（有复用）** | **~342 ≈ 34%** |
| 合计（无复用） | ~442 ≈ 44% |

⇒ 720p 之后总线上限不再是主要矛盾（当年 1080p + 无复用是 99% 压线）。
但**整屏重画**依然是浪费（一帧 2.64 MB 写 = 543 MB/s 跑满 4.9 ms），所以**脏区局部重画是默认做法**；
alpha 每层多一次"读回目的"，依然**只对脏区做，禁止整屏**。

实测校准（上板，见 `实测数据.md` §2）：

- **写带宽 543 MB/s** 是实测定下来的基准（1080p 整屏 FILL 那次量的，显示全程开着）；
- 720p 整屏 FILL 推算 **≈ 4.9 ms（帧周期的 29%）**，连同显示读合计 **≈ 709 MB/s ≈ 71%**；
- 消隐窗只有 30 行 ≈ **667 µs** ⇒ "单缓冲 + 消隐窗"最多改写约 362 KB（33 个 64×64 精灵，只算写一次）；
  1080p 时代实测 8 个 64×64 脏区 + FENCE = 813 µs 就已经超过窗口 ⇒ **动图必须走双缓冲 + 脏区**。

### 6.4 撕裂与带宽无关

| 现象 | 真正的原因 | 解法 |
|---|---|---|
| 撕裂（上下是不同帧） | **显示正在读的缓冲被人写了** | **双缓冲 + 只在帧边界翻页** |

> **带宽再紧张，只要读写的是两块不同缓冲，就不会撕裂；带宽再宽松，只要读写同一块，照样撕裂。**

## 7. 帧流水线与软硬件分工

### 7.1 双缓冲

```
buffer A   [HDMI 扫 F0]        [画 F2         ]    [HDMI 扫 F2]
buffer B   [画 F1     ]        [HDMI 扫 F1    ]    [画 F3     ]
             T0                 T0+16.7ms(翻页)     T0+33ms(翻页)
```

- 渲染与显示并行叠一帧；翻页 = 在帧边界换 front/back 指针（无数据搬运）；
- 慢渲染：没画完就不翻 → 重复扫旧帧 → 掉 FPS 不错画。

### 7.2 与显示的握手（沿用已上板验证的两条约定）

1. 收到 `lineBuffer_frame_start` 之后**才开始写后台缓冲** —— 那一刻显示已经切走，读写不碰同一块；
2. 整帧画完（写响应全部收齐）才拉 `acc_frame_done` 单拍脉冲。

> **为什么不能自己提前动笔**：显示是连续读的（帧尾只停手 41 行 ≈ 607 µs），没有"读完一帧就休息"这回事；
> 提前动笔就可能写到正在显示的那块上 ⇒ 撕裂。

### 7.3 CPU 的两种角色

| 模式 | CPU 干什么 | 像素活谁干 |
|---|---|---|
| 加速模式（产品） | 游戏逻辑 + 下发命令 | 加速器 |
| 软渲对照（baseline） | 游戏逻辑 + 亲自搬像素 | CPU（必然慢，这正是演示目的） |

同屏对比 = 同一份场景，两种方式各跑一个半区（左半加速器 / 右半 CPU），屏上实时显示两个 FPS。
**已上板实测 CPU 5 fps : 加速器 60 fps**（见 `实测数据.md`）。

> CPU 软渲是**故意慢的基线**，不需要突发写：逐像素写 DDR = 慢，正是演示目的。

### 7.4 一帧单写者

| 场景 | 规则 |
|---|---|
| 区域不重叠 | 可并发写，无先后；DDR 只做带宽仲裁 |
| 区域重叠 | 不能并发；串成有序命令流 |
| 同一 back 被多方写 | 翻页被迫等最慢 → 各自独立缓冲对才解耦 |
| 一帧一主 | 加速模式硬件写 / 软渲模式 CPU 写 |

## 8. AXI 接入结论（协议速查见 `../参考/AXI总线解析.md`）

### 8.1 全链路 ID 统一为 0

链路各段 ID 位宽：CPU 主口 **8** / `io_ddrMasters_0` **4** / `Axi_Mux` 主端 **8** / DDR3 从口 **4**
⇒ **截断点在 Mux 主端 → DDR 从口**。

`Axi_Mux` 在 Normal 模式下**响应归属由它自己的信息 FIFO 记账决定，与 ID 内容无关** ⇒ 截断无害。
**纪律：所有主设备 AXI ID 硬编码 `8'h00`**（0 是截断的不动点），顶层做**显式切片**，别让综合器隐式截断。

> ⚠️ 不要做的事：把 `ID_MODE_SEL` 改成 `"Extend"`（主端 ID 变 9 位，离 4 位更远）；
> 去改 DDR3 IP 的 ID 位宽（加密 IP，风险高且没必要）；用不同 ID 区分响应（本方案单 outstanding，不需要）。

### 8.2 `Axi_Mux` 的三条结构限制（硬限制，从源码读出）

| # | 限制 | 影响 |
|---|---|---|
| 1 | **AW / AR 按笔仲裁，但 W / R 是"整笔独占"** | 某个主的一笔突发一旦上了 W 或 R，**不跑完其他主都得排队**（W 与 R 是两条独立通路，读和写可同时进行） |
| 2 | **信息 FIFO 深度 = 系统级 outstanding 上限**（AW2W 8 / W2B 8 / AR2R 16），且**背压是全局的** | 一个主把 FIFO 占满，整条 AW/AR 对所有主都停 |
| 3 | 仲裁只有**轮询**与**固定优先级（S0 最高）**两档 | **没有带权轮询、没有老化提升** ⇒ 显示实时性**靠缓冲，不靠仲裁** |

由此定下三条设计结论：

1. **每个主用单 outstanding**（一次只发一笔，等回来再发下一笔）—— 多 outstanding 会吃满 FIFO 并霸占 W/R，在共享总线上是负面设计；
2. **突发长度做成运行时可变** —— W/R 整笔独占 + 仲裁只有两档 ⇒ **突发长度是唯一的公平性旋钮**
   （256 拍 = 单笔独占 2.56 µs；64 拍 = 0.64 µs，CPU 响应更快）；
3. **显示实时性靠行块预取缓冲**，不指望仲裁器偏心。

### 8.3 四个主设备（现状）

| 口 | 谁 | 写 | 读 | 延迟敏感 |
|---|---|---|---|---|
| **S0** | CPU（`io_ddrA`） | ✅ 软渲 | ✅ 取指 / 取数 | **高** |
| **S1** | 显示取数（lineBuffer） | ✗ | ✅ 读帧缓冲 | **高**（欠载即花屏） |
| **S2** | 加速器读（`DDRSource`） | ✗ | ✅ 读源 | 中 |
| **S3** | 加速器写（`WriteController`） | ✅ 写目的 | ✗ | 中 |

> `Cfg_Cnl_Mask` 必须**全 1 且位宽与通道数一致**，少一位对应通道直接哑掉。
> 加速器占**两路 S 通道**（S2 读 / S3 写）：五条通道各自独立仲裁 ⇒ 块拷贝的"读源"和"写目的"
> 可以同时在飞（同一条通道上做不到这件事）。

### 8.4 拆笔的硬约束（上板踩过，锁死过整条 AXI）

**任何主机一旦交出 AW，就必须把这一笔的 `WLAST` 也交出来**，否则 W 通道被永久锁死 ⇒
整条 AXI 上所有写全停（CPU 打串口也停，因为 APB 写要过同一个 W 通道）。
现象是"**CPU 没死，只是再也打不出字**"，极容易误判成芯片挂了。

踩的坑：拆笔公式里那一除，在**行首地址未 16 字节对齐**且**页尾不足 16 字节**时会得 0：
`(4096-4092)>>4 = 0` ⇒ `cmd_wr_len = 0-1 = 8'hFF`（主机以为要发 256 拍）⇒ 永远停在等第 256 拍。

**定下来的三条规矩**：

1. **突发地址一律清低 4 位**（`{addr[31:4], 4'b0000}`）；行首真实偏移由**首拍 WSTRB 遮头**体现，不进 `AWADDR`；
2. 清低 4 位后 `4096-off` 必是 16 的整数倍且 ≥16 ⇒ **拆笔结果恒 ≥1**，0 拍死锁从结构上不可能；
3. **TB 的从机模型必须查 `WLAST` 正好落在 `AWLEN` 定的那一拍**（原来只按 `AWLEN` 数拍、不看 `WLAST`，"说好 256 拍只来 34 拍"在仿真里不报任何错）。

## 9. 全局纪律（改动前先过一遍）

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | **74.25 MHz 像素通路（`bufferUnpacker` → `HDMI_Top`）一个字节都不动** | 工程**没有 SDC**，TMDS 时序只能靠综合结果；动它等于同时冒时序与布局两个风险（有过"加一根顶层线板子起不来"的教训） |
| 2 | **能挂在 100 MHz 侧做的事，不要放进像素通路** | 同上。alpha / 显示索引可读 / 调色板写口都在 100 MHz 侧或写侧 |
| 3 | **不要为功能加跨模块的"解码结果"线** | 曾为此加过 `line_src_en` / `line_bg_rd`，最后改成"各消费者自己解 `flags`（三处实现）"，线全删了 |
| 4 | **改 `flags[2:0]` 的模式表要一起改三处**（`DDRSource` / `PaletteSource` / `Compositor`） | 接口契约只有一张表，实现在三处 —— 这是当前做法的代价 |
| 5 | **素材 / 调色板一变就必须重新综合** | 它们是 BRAM 初值，在生成 bit 阶段烧进去 |
| 6 | **改完运行目录里的 `palette.hex` 要同步到各 TB 目录** | TB 的 DUT 和参考都读运行目录；`run_tb.ps1` 会把 TB 目录下的 hex 同步进 `hex/`，两份不一样会报一堆假错 |
| 7 | **TB 里读调色板当参考，数组必须是 32 位**（`reg [31:0] pal [0:255]`） | 文件是 8 位十六进制；按 24 位读会让 `$readmemh` 丢值 ⇒ 那一项是 X（踩过 3 次） |
| 8 | **等完成不要猜延时**：统一用 `waitCmdDone(快照 + n)` / `waitFrame`，且必须带超时 | 猜少了读到没画完的图；卡住时板子会变哑。判据写成 `!=` 快照是错的（完成 1 条就被当成全完成） |
| 9 | **重新烧 app 不复位 FPGA** ⇒ 显示侧 APB 寄存器是保留的 | 每次先写确定值（`enable(0)` + `setSplit(0)`）再灌图 |
| 10 | **"多路源同时用"是新契约**：加源之前先问两件事 | ① 我取走的条件跟下游收下的条件是不是同一个？② 我多出来的那一拍谁负责丢掉？（alpha 第一次让两路同时跑，就踩在这里，见 `硬件_加速器.md` §5.4） |

> ★ 另有一条**显示相位免疫**：每帧画完后台后，把显示基址的两个槽都写成刚画好的那一块。
> 理由与做法见 `硬件_显示通路.md` §9。

## 11. 术语表

| 词 | 含义 |
|---|---|
| **CI** | 自定义指令（Custom Instruction）：CPU 发命令的通道，**一条命令 = 两条 CI** |
| **FENCE** | 帧结束命令：等前面所有绘制落盘后才拉 `acc_frame_done` |
| **行任务（line task）** | 一条命令展开后的一行：`line_start` 那一拍把地址 / 宽高 / flags 广播给各源 |
| **源① / 源②** | 源① = DDR 读回的一行（BLIT 的源，或 alpha 的背景）；源② = 片上 PRAM 调色板素材 |
| **PRAM** | 片上素材 RAM：32768 字 × 32 位 = 4 个 8bpp 索引 / 字，共 128 KB |
| **拍对齐 / 像素对齐** | 拍对齐 = 摆进目的 16 字节 AXI 拍（在 `DDRPacker` 做**一次**）；像素对齐 = 一拍 4 个整像素（各源自己做） |
| **脏区 / 重建** | 只重画变化的矩形：先铺背景，再按 z 序重放该区内的**全部**元素 |
| **画家算法** | z 序 = 命令下发顺序，后画的盖前面的（硬件**没有** z 缓冲） |
| **显示相位免疫** | 每帧把显示基址两个槽都写成刚画好的那块，避免"软件和硬件索引差一位" |
| **ck** | 颜色键控：等于键色的像素不写（透明） |
| **AB** | alpha 混合 |
