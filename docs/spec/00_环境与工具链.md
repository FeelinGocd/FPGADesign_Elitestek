# 00_环境与工具链（团队必读，由环境 Owner 维护）

> 目标：任何人 clone 本仓库后，能按本文档把软核环境复现出来。
> 原则：**版本锁定、路径约定、配置变更走 Owner**。

## 1. 版本锁定表（Owner 填）

| 工具 | 版本 | 下载/来源 | 备注 |
|---|---|---|---|
| Efinity | 例：v2023.2.x | https://www.elitestek.com/efinity/ | 全员必须一致 |
| Sapphire SoC IP | 例：vX.Y | Efinity IP Manager 内 | 与 Efinity 配套 |
| RISCV-SDK / GCC | 例：r11.2 | 随 Efinity 提供或官网 | 编译 C 固件 |
| 仿真器（ModelSim/Questa） | 例：2021.4 | 授权/自备 | 协同仿真用 |
| 开发板驱动/下载工具 | — | 群文件 | — |

> ⚠️ 任何工具版本升级，必须先更新本表并通知全员，禁止个人私自升级。

## 2. 软核生成步骤（Owner 首次填写，含菜单路径/截图位置）

1. 打开 Efinity，新建工程（建议工程路径固定为 `project/`，不入 Git）
2. 菜单路径：`[IP Manager / Sapphire SoC Builder]` → 新建 SoC 实例
3. 关键配置项（逐项记录，与 docs/spec 契约一致）：
   - CPU：`[RV32 / RV64]`，主频 `[___MHz]`
   - 内存：片上 RAM `[___KB]`；外部 DDR3 `[___MB]`
   - 外设清单：`[UART / GPIO / AXI-Lite 接口 / ...]`
   - AXI 数据位宽：`[32/64/128]`；外设基地址见 `02_寄存器映射.md`
4. 生成输出目录：`[project/.../soc]`（确认被 .gitignore 覆盖）
5. 生成后**先用官方/仓库 smoke test 验证**（见第 4 节）再分发给队友

## 3. 新队员环境搭建清单（照做）

- [ ] 安装与版本表一致的 Efinity（**安装路径不要中文/空格**）
- [ ] 从群文件下载《SoC 生成包 vX》（Owner 打包），解压到 `project/`
- [ ] 打开工程，确认 IP 实例存在且无报错
- [ ] 编译运行 `smoke test`（串口打印/点灯），通过 = 环境 OK
- [ ] 仿真：确认 ModelSim 能跑 `sim/tb/` 下任一 testbench

## 4. Smoke Test（环境一致性验证）

仓库提交一个极简固件（`src/smoke/`）：
- 功能：初始化 UART → 打印 `"SOC OK: version=xxx"` → 点 LED
- 通过标准：串口收到预期输出 = 软核/内存/外设配置与契约一致

> 任何新队员或环境变动后，先跑 Smoke Test，再开始并行开发。

## 5. 常见坑（Owner 持续补充）

| 现象 | 原因 | 解决 |
|---|---|---|
| 综合报 IP 找不到 | 路径不对/版本不符 | 确认解压路径与版本表 |
| 固件地址错乱 | 内存映射与 02_寄存器映射.md 不一致 | 以契约文档为准重新生成 |
| 仿真启动不了 | 仿真器版本不匹配 | 对照版本表 |

## 6. 变更流程

1. 需求方提出（加外设/改内存/升版本）→ Owner 评估
2. Owner 本地重新生成 → 更新契约文档（02/04 等）→ 打包 v+1 传群文件
3. 全员拉取 Git（契约更新）+ 下载新包，重跑 Smoke Test
