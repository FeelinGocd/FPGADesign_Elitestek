## 2. 带宽

### 2.1 口径

- 显示全程开着（扫描读一直占着读通道）；
- 计时用 GPU_2D 寄存器自报的 `BUSY_CYC`（100 MHz，1 周期 = 10 ns）；墙钟口径在 mode 9 用 CLINT 交叉验算过；
- 写拍 × 16 字节 = 写字节数。

### 2.2 实测（2026-10-01，`LB_TEST_MODE = 12`）

| # | 负载 | 写 | 读 | 忙 | 换算 |
|---|---|---|---|---|---|
| ① | 整屏 FILL 1920×1080 | 388800 拍 = **6075 KB** | 0 拍 | **11455 µs** | 写带宽 **543 MB/s**；占帧周期（16667 µs）**69%** |
| ② | 8 个 64×64 BLIT + FENCE | 6656 拍 = 104 KB | 7168 拍 = 112 KB | **813 µs** | 脏区 98 KB 像素 → 实写 104 KB（+6%）、实读 112 KB（+14%） |

**由 ① 定下来的三条数**

- **整屏写带宽 ≈ 543 MB/s**（显示开着的最坏情况）—— 这是后面所有带宽账的基准；
- 1080p 时加显示读 373 MB/s ⇒ 总线 **916 MB/s ≈ 92%**，所以**动图必须走双缓冲 + 脏区**；
- 消隐窗只有 41 行 ≈ 607 µs ⇒"单缓冲 + 消隐窗"改写整帧不成立（8 个 64×64 脏区要 813 µs）。

### 2.3 现在这一版（1280×720）的账

| | 公式 | 结果 |
|---|---|---|
| 显示读出 | 3840 B/行 × 720 行 × 60 | **166 MB/s**（2.64 MB/帧） |
| 一行读出 | 3840 B | 240 拍（一行 3 笔，`ROW_STRIDE` 仍 5760） |
| 整屏 FILL 一帧 | 1280×720×3 = 2.64 MB ÷ 543 MB/s | **约 4.9 ms ≈ 帧周期的 29%**（推算，沿用 543 MB/s） |
| 显示读 + 整屏写合计 | 166 + 543 | **≈ 709 MB/s ≈ 71%**（按 1.0 GB/s 实际可用口径） |
| 消隐窗（30 行） | 30 × 22.2 µs | **667 µs** ≈ 可改写 362 KB（约 33 个 64×64 精灵，只算写一次） |

⇒ 720p 之后**余量比 1080p 时代松了口气**（显示读从 373 降到 166 MB/s），但"整屏重画"仍然贵，
**脏区局部重画仍然是默认做法**（`软件_驱动与API.md` §6）。

> DDR3 理论 1.6 GB/s（读写共享），实际可用 **1.0~1.2 GB/s**。

## 3. 命令开销

### 3.1 历史一次实测（2026-10-02，FILL-only，**不可外推**）

条件：32 个 16×16 方块、全屏活动区 1920×1080、速度随机 ±2/±3 像素/帧、跑 600 帧、**命令全是 FILL**。

| 项 | 结果 |
|---|---|
| 帧率 | **60 fps**（600 帧 / 9980 ms，锁在显示帧边界上） |
| 命令数 | **64 条/帧**（32 条铺底 + 32 条画元素）+ 1 条 FENCE |
| 忙时间 | **355 µs/帧**（占 16.7 ms 的 **2.1%**） |
| 自检 | 172800 个采样点，不一致 **0** |
| 元素重叠帧 | 110 / 600（z 序 + 裁剪规则被真正考到） |

⇒ 约 **5.5 µs/条命令**。⚠️ 那次全是 FILL，之后的硬件多了 PRAM 精灵源、alpha（每条命令多一次 DDR 读回）、
合成命令（3 条 CI）⇒ **每条命令的开销结构已经不同，不能用 5.5 µs 去推元素数上限**。

### 3.2 CPU 侧的已知账

| 项 | 值 | 口径 |
|---|---|---|
| 一条命令 = 2 条 CI | 约 **20 拍/CI** | 按 `-O0` 估 |
| CPU 自己写帧缓冲 | **~17 MB/s** | 上板实测（逐像素写 DDR） |

**TB 侧踩过的坑（写新 TB 时照做）**

1. **调色板参考数组必须 32 位**（`reg [31:0] pal [0:255]`）—— 文件是 8 位十六进制，按 24 位读会丢值 ⇒ 那一项是 X
   （症状是"期望值全 X、满屏不一致"，看着像 RTL 坏了，**踩过 3 次**）；
2. **运行目录的 `*.hex` 要跟着 `project/GamingPlayUnit/hex/` 更新**（见本节开头那条）；
3. **从机模型必须查 `WLAST` 落在 `AWLEN` 定的那一拍** —— 只按 `AWLEN` 数拍的模型，"
   说好 256 拍只来 34 拍"不报任何错（这就是当初漏掉拆笔死锁的原因）；
4. **必须有一条"逐字节比绝对内容"的用例** —— 只比"两遍一致 + 掩码"查不出常数色被转反这类错；
5. **flags 加宽、端口改名这类"接口变更"要同步全所有 TB** —— 2026-10-17 就因 `flags` 从 7 位变 8 位，
   `tb_CmdBuffer` 的 `check_slot` 还按 7 位步长取第 2 格 ⇒ 假 FAIL。

### 5.18 580 敌弹历史采样与顶部 HUD 修复 —— 2026-10-29

最终运行配置为 **612 个物理弹槽 = 580 敌弹上限 + 32 个玩家预留**。主机回归验证 16 种 Boss 招式峰值均为 **580**，三个 Boss 阶段峰值也均为 **580**；612 发固定压力通过 1800 步生命周期、射程和碰撞检查。默认 BIN 为 **79,722 B**，SHA256 为 `4443f013a74962612977d9dda682ad1616936808dfafbb33ba4ac3d0de1b3258`；RAM 占用 **116,960 / 126,976 B**，剩余 **10,016 B**。

通过 JTAG 下载后，CPU 暂停期间整块 79,722 B 回读与 BIN 逐字节一致。随后通过 COM5 重新开始、按 `1` 进入 Boss、开启无敌，并让角色在八个方向间持续移动；24 秒内每 0.5 秒查询一次文本 `S`，共取得 **48 个有效快照**：

| 指标 | 结果 |
|---|---:|
| 活跃敌弹峰值 | **580** |
| 总弹数峰值 | **581** |
| FPS 最低 / 中位 | **56 / 59** |
| 每帧命令数最大值 | 690 |
| 渲染队列最大丢弃 | **0** |

采样中有 5 个一秒窗口低于 59 FPS，最低 56 FPS；因此 580 发并未达到全程锁定 60 FPS。60 秒和 64 秒的 600 发实验配置及其临时镜头、绘制和追帧调整已经撤销，当时只保留纯 580 基线与原有的 60 Hz 固定逻辑。采样结束后已关闭测试模式、释放串口并恢复普通游戏运行。

道具拾取文本改为屏幕水平居中、顶部 `y=2` 的固定 `400×24` 区域，绘制和擦除共用同一矩形；连续拾取长文案后再换成短文案，不会保留上一段尾部。`BOSS` 全称固定在血条左侧，锁血清怪和换阶段期间持续提交。HUD 像素回归覆盖 2/3 缓冲、提前恢复和预更新的全部 8 种组合。

### 5.19 500 敌弹稳定总弹池、FPS 显示口径与 Inner Eyes 叠加弹道 —— 2026-10-29

当前主工程恢复为已验证稳定的 **532 个物理槽 = 500 敌弹上限 + 32 玩家预留**，敌人上限只由 `GAME_ENEMY_BULLET_CAP` 配置，物理池大小自动计算。Inner Eyes 现按“**每拾取1件增加1条玩家弹道**”工作，基础1条加 N 个 Inner Eyes 后形成 `1 + N` 条弹道，重复拾取继续累加。每件同时提供射击间隔 **+5 帧**、射程 **+3**、伤害 **-1**。

主机完整回归通过：16 种 Boss 招式和三阶段峰值均为 **500**，532 个物理槽压力测试通过；道具回归确认 1/2/3 件 Inner Eyes 分别形成 **2/3/4** 条弹道，并覆盖与 Uranus 的组合和拾取顺序。HUD 的 MOVE 和 RATE 已改为读取实际道具结算值。

HUD 的 FPS 统计不再直接截断 1001 ms 等正常计时误差窗口：最近窗口内完成 60 帧时按四舍五入显示 **60**，真实 59/55 帧仍分别显示 **59/55**，不会强制显示 60 来掩盖掉帧。550 敌弹在静音正式固件、持续移动和真实 Boss 发弹下实测降到 **57–59 FPS**，因此不保留该档。500 敌弹在同条件连续移动采样中 **12 个窗口全部为 60 FPS**，峰值达到 **500**，渲染队列丢弃为 **0**。采样后已关闭测试/无敌状态，重开普通游戏并释放 COM5。

当前 BIN 为 **79,794 B**，SHA256 `DF9035B08F50C1AEA8EE573D565CAF7D91E50F16F9A55F952417364EA79E16FE`；RAM 占用 **114,160 / 126,976 B**，剩余 **12,816 B**。启动与 Boss 日志为 `shot_cap=500`。41 对 `game/*.c,h`、`src/main.c` 与 makefile 上传副本逐字节一致。尚未进行多件 Inner Eyes 的实机连续拾取验收。
