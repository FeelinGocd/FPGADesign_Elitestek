## 4. 地图刷新：保留当前成果

用户的设计原则是：**固定地图池与 interact 解耦；同类 1×1 房间主要变化是门与交互项目，应被动更新变化区域。** 不要退回每次换房都重画两块整屏的路径。

当前实现要点：

- 直接复用 DDR 的 C/D framebuffer，没有为每间房新增图像缓存。
- 每块 framebuffer 有固定地形身份、有效位图和当前准备状态；这组元数据约 **420 B**，不是一张地图的像素副本。
- 优先保留最近一个大房间的地形身份。小房间只使覆盖区域失效；大房间入口先准备当前视口。不同大房地形或镜像不能错误复用。
- 离房前用已有 dirty grid 标记角色、弹幕、HUD、门、interact 等旧覆盖范围。有效位只代表固定地形，不代表交互状态。
- 异图构建按 `ROOM_BUILD_ROWS=2`、`ROOM_BUILD_BUDGET_MS=6` 的默认软预算推进；旧前台保留到后台入口视口完整后才切换。
- 旧版 `ROOM SYNC` 复制阶段已移除。另一块缓冲在后续正常帧按需修复。
- 已修正 `scene_restore` 在完整补齐视口后又恢复旧脏区造成的重复绘制。需要准备背景时走准备路径，普通帧再走局部恢复。
- 初始化、R 重开和显式强制重建仍可全量刷新。不能为减少统计值而删掉这些必要路径。

性能判断：命令数不是唯一依据；大面积绘制、DDR 访问、alpha 背景读回、显示边界等待和重复恢复均影响时延。用户以前的 1080p 压测能到约千条命令才掉帧，不代表换房的相同命令数具有相同成本。门绘制不要无故改为 alpha；遵循当前素材透明规则和绘制 API。

细节和回归依据：

- `<SW>/verification/terrain_reuse_v1.md`：当前机制、元数据、真实 PRAM 主机像素对比及重复恢复修正。
- `<SW>/verification/room_build_v1.md`：前一版 BUILD+SYNC 记录，**其中 SYNC 行为已经过时**。
- 用户最新反馈附件 `66120b63-a30f-437a-86e8-b69766757660`：反馈“稳 57 帧”。附件路径只用于追溯，交接者不一定能访问，不要据此编造更多具体耗时。

## 6. 素材编号与本次花图结案

生成链：

```text
res/pic/... 图片
  → tools/img2hex/pic2pram.py
  → project/GamingPlayUnit/hex/assets.hex + palette.hex
  → tools/img2hex/output/assets_desc.h + report.txt
  → <SW>/peripheral/APB0/gpu2d/assets_desc.h
  → 用户编译并下载配套 FPGA bit 流和 C 固件
```

`assets.hex` 存 8 位调色板索引，每 32 位字四个像素；描述表提供 PRAM 字基址、跨距、宽高。调色板项为 AARRGGBB。整个素材集一起生成，新增图可能改变后续编号、字基址，调色板也可能变化，不能只更新单张索引数据。

当前插入的是 `SpecialEffect_TriPrism_00/01/02`，每张 24×24、144 字，共增加 432 字；插在子弹之前。

| 素材 | 当前 ID | PRAM 字基址 |
|---|---:|---:|
| TriPrism 特效三帧 | 72／73／74 | 18816／18960／19104 |
| 普通弹 A | 75 | 19248 |
| 火焰弹 B | 76 | 19504 |
| Uranus 弹 C | 77 | 19760 |
| 普通门 | 95 | 25136 |
| 隐藏入口 | 102 | 27696 |

这些是 **2026-10-25 快照**，以后以生成头文件为准。C 使用 `ASSET_*` 符号，不要写裸 ID；逻辑道具的 `ITEM_*` 顺序不能跟素材排序一起变。

本次故障过程与确认依据：

1. 用户反馈人物与地形正常，子弹／道具／门异常，范围与插入点一致。
2. 已核对源图、两份生成头文件、hex／palette 和最新 ELF 的 `g_assets` 全部一致；反汇编中的子弹 ID 为 75～77、普通门 95、隐藏入口 102。
3. 已只读核对综合网表 PRAM 初始化：128 个存储块的数据全部匹配当前 `assets.hex`，不只是看文件时间。
4. **用户最终确认未换 bit 流文件，问题解决。** 此结论优先于前面的排查猜测；尚未加入启动素材读回自检，不要写成已经实现。

常用检查，在仓库根目录运行：

```powershell
python tools/img2hex/pic2pram.py --target project --dry
# 确需重新生成时去掉 --dry；默认不写 code 归档。
python tools/img2hex/check_assets.py --sources-only
python tools/img2hex/check_assets.py --skip-bitstream
python tools/img2hex/check_assets.py
```

`--sources-only` 校验源图与生成物；`--skip-bitstream` 额外核对已有 ELF 的素材表。默认命令对 bit 流仅检查时间，**不能证明板上加载的版本正确**。本次写交接时重新执行 `--skip-bitstream`，结果 PASS：105 assets，源图、ROM／palette、头文件和 ELF 一致。

当前 PRAM 剩余 **4304 字，约 16.8 KiB**；这是 FPGA 素材存储空间，不能和 C 固件 RAM 余量混算。
