# 软件 · 驱动、绘图 API 与脏区

> 适用：RISC-V 端的 C 代码（`peripheral/` 驱动 + `project/src/` 的 demo）。
> 命令格式与硬件语义见 `硬件_加速器.md`；系统级约定见 `设计总纲.md`；实测数字见 `实测数据.md`。

---

## 1. 分层与缓冲模型

```
应用 / demo
   │  (1) 命令层    CI_gpu2d_*                        一条命令 = 一次绘制
   ▼
2D 加速器 GPU_2D（写 DDR）
   │  (2) 用户层    user_gpu2d_* / user_lineBuffer_*  提交 / 等待 / 翻页 / 显示开关
   ▼
显示通道 lineBuffer（读 DDR 上屏；现用现取，片上只缓存两行）
```

- **命令层**只负责"描述一次绘制"；**用户层**负责**时序与纪律**（发完等完成、翻页、显示开关）；
- 显示通道硬件按 HDMI 节拍自己读 DDR，软件只能用 enable 控制它开 / 关。

| 缓冲 | 用途 | 说明 |
|---|---|---|
| A / B | 分屏时的左右两块 | 与 C / D 互斥使用 |
| C / D | 全屏双缓冲 | **当前主用** |

- 每个缓冲 = **一整帧**（1920×1080×3 = 6.2 MB）；
- 显示读的那块叫**前台**，绘制写的那块叫**后台**；
- **翻页只发生在显示的帧边界上**（硬件在帧边界消费 DONE，软件只负责"交帧"）。

### 2.1 alpha 用法（四条规矩）

```
CI_gpu2d_spriteAlphaRect(asset_base_word, stride_word, fb_back, x, y, w, h, extra);
/* extra = 0 就是纯 alpha；可拼 GPU2D_MODE_CKEY_EN | GPU2D_FLIP_X | GPU2D_FLIP_Y */
```

```
结果 = 背景 + (精灵 − 背景) × α / 255
        └── 背景 = 【这条命令要写的那块矩形】—— 硬件自己读回来，软件不用给
        └── α    = 【调色板每一项的高 8 位】（一项 = AARRGGBB），不在参数里
```

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | **α 在调色板里** ⇒ 一个索引 = 一种 (颜色, α)。画素材用**固定档位**（0/128/255），别用连续渐变 | 像素数据只有 1 字节索引，装不下 α；同色不同 α 会塌成同一项 |
| 2 | **只支持 PRAM 精灵**（`flags[3]=1`） | DDR 帧源没有 α（那要 4 字节 / 像素的源格式） |
| 3 | **别拿它刷整屏** | 读回量 = 矩形那一段；整屏读回 = 373 MB/s 额外读，直接超 DDR |
| 4 | 目的里**得先有东西**（先铺底再叠） | 读回来的就是目的现状；叠多层是可以的（后画的读回前面画的结果 = 普通画家算法） |

**和 ck 的关系**：两者可以**同时开**（`extra |= GPU2D_MODE_CKEY_EN`），硬件把两个掩码**相与** ——
ck 管"这个像素整个不写"，α 管"按比例写"。素材若全是硬边（α 只有 0 / 255），两者效果等价。

## 3. 时序纪律（必须成对出现）

| 接口 | 语义 |
|---|---|
| `gpu2d_exclusive_begin()` | **关显示**，准备做一次大块绘制 |
| `gpu2d_exclusive_end(target)` | 等这批命令画完 → **再开显示**（取数从帧边界重新对齐） |

**三条硬规矩**

1. **大块绘制（整屏 / 几 MB）**：`exclusive_begin()` → 画 → `exclusive_end()`。
   原因：显示的取数是"现用现取"。DDR 被写请求占满时显示会被饿到；一饿就落后，
   而且**自己追不回来**（每行两边 1:1 前进，落后多少就永远落后多少），之后整幅画面永久错位
   （上板实测：横向错开约 520 像素）。关显示时流水线排空，再使能时取数从帧边界干净起步。
2. **每帧动画**：画后台 → `fence` + `waitFrame` → **等显示真的翻页** → 再画下一帧。
3. **永远不在正在显示的那块缓冲上画** —— 会撕裂，自检也会大面积错。

> **例外**：脏区小更新不用关显示（双缓冲下显示读的是另一块，量小也饿不到）。
> ★ 还要注意"**节拍锁 60 Hz**"：FENCE 完成只表示 DONE 置位，显示要到**下一个帧边界**才消费它。
> 软件比 60 Hz 快的话，两次 FENCE 只换来一次翻页 ⇒ 自己以为的"后台"会和显示实际播放的那块错位。
> 做法：FENCE 后轮询 `lineBuffer_getDoneAcc()` 直到回读变 0（= 已被消费），自然锁到 60 Hz。
> **上板实测踩过**：不锁时 loop 跑到 77 fps，自检成片报错。

## 5. 图层与 HUD

### 5.1 现状：z 序是显式的吗

**z 序 = 命令下发顺序**（后发的盖前面的，画家算法）。硬件**没有** z 缓冲，也不需要。
为了让"元素数组怎么摆"不影响画面，软件加了**层号 + 元素 id**：**绘制顺序 = 按 (层号升序, 元素 id 升序) 稳定排序后的顺序**。

| 层号 | 名字 | 放什么 |
|---|---|---|
| **0** | `LAYER_MAP` | 地图 / 地面 |
| 8 | `LAYER_GROUND_MARK` | 地面标记：参考线、网格、坐标尺 |
| 32 | `LAYER_PROP_BACK` | 背景物件（角色可以走到它们**前面**） |
| 64 | `LAYER_ACTOR` | 角色 / NPC / 敌机 |
| 96 | `LAYER_PROP_FRONT` | 前景物件（**挡住**角色） |
| 128 | `LAYER_FX` | 特效 / 粒子 / 弹幕 |
| 192 | `LAYER_HUD` | HUD：血条、计分、字幕 |
| 224 | `LAYER_DEBUG` | 调试覆盖：帧率、探针框 |

```
typedef struct {
    int x, y, vx, vy;   /* 位置 / 速度 */
    u32 color;          /* 颜色（或素材编号 + 帧号） */
    u8  layer;          /* ★ 层号 */
    u16 id;             /* ★ 稳定排序用，创建时分配后不改 */
} elem_t;

void layer_rebuild_order(void);   /* 按 (layer, id) 重建顺序表；元素表被打乱后必须重调 */
```

- **不能用不稳定排序**：同层元素的先后会随机变化 ⇒ 重叠画面抖动；
- **验证方法**：把元素表 **shuffle** 之后画面必须**逐像素不变**。

### 5.2 HUD 怎么放（零 RTL，已实现）

**（加速器那半）做法：把 HUD 当成"层号最高的一批元素"，跟着每帧的重放画一遍。** 每帧四步：

```
① 擦全部元素的旧位置        ② info_erase()  —— 擦数字框（层 0 的背景）
③ 按 (层号, id) 画全部元素   ④ info_digits() —— 画数字（层 192，永远最后）
```

② 必须在 ③ 之前（它是背景层）；④ 必须在 ③ 之后（HUD 永远在最上）。每帧多几条命令。

| 半幅 | 游戏内容（背景 + 元素） | HUD（覆盖层） |
|---|---|---|
| **左半（加速器）** | 加速器画（CI 命令） | 加速器画：HUD 作为层 192 的元素，进入"擦全部 → 按层序重放全部"这一遍，层号最高 ⇒ **最后画**，自动压在方块上；被方块擦到也无所谓，下一帧重放会补回来 |
| **右半（CPU）** | **CPU 逐像素写**（`cpu_fill(...)`）—— 这就是"纯软件"的对照对象 | **也由加速器画**（同上，层 192），左右同款同位置 |

> ★★ **对比的口径是帧率（FPS），不是像素归属**。右半的**游戏内容 100% 由 CPU 逐像素写**；加速器只往右半写那一条 HUD（两位数字 + 它的底色框）。
> 这条是**有意的例外**，理由两条：
> ① 左右两半的数字必须**同款、同位置**才方便实时对比，而 CPU 自己画就得自带一份点阵字模（CPU 读不到 PRAM，见下）；
> ② HUD 只有两条命令、占比可忽略，而"**加速器一边画整屏内容、一边还画着 HUD，依然锁住 60 fps**"本身就是硬件加速效果的证据。
> ★ 代价与纪律：右半在**同一帧**里被两个写者碰过（CPU 先写完 + `data_cache_invalidate_all()`，加速器随后只写 HUD 那一小块）⇒ **顺序必须保证**，且除 HUD 那一小块外，加速器一个像素都不许碰右半。
> ★ CPU **读不到 PRAM**（片上 BRAM 没映射到总线）⇒ 它不能复用 PRAM 里那套 32×48 数字素材。
> 如果哪天要"绝对纯净的右半"，改法就是 CPU 自绘 5×7 / 8×8 点阵字模（C 数组，字小 + 只在数字变化时重画）；**现在不做**，记在这里备查。
> ★ **分屏对比只用方块**（不做精灵版）：CPU 要画精灵就得再存一份真彩素材到 DDR/app 里，两份素材还得同步 —— 赛题基础要求举的例子本来就是"大量方块的随机移动"，够用。

**为什么不用"背景底版"**：擦除是往旧位置盲铺底色，从 DDR 读回来只有合成结果（图层已经没了）。
用另一份背景底版 BLIT 回来虽然可行，但擦除从"只写"变成"读 + 写"，带宽直接翻倍 ⇒ 超预算。
**按层重放是正确解。**

## 6. 动图与脏区（每帧只重建变化的那几块）

### 6.1 结论先行

| 问题 | 结论 |
|---|---|
| 动图怎么做 | **双缓冲 + 脏区"局部重放"**：每帧只重建变化的那几块 |
| 为什么要脏区 | 整屏重画 = 11.46 ms/帧（占帧周期 **69%**）+ 总线 **92%**；CPU 那半就没带宽了（分屏对比会饿死 CPU） |
| 能不能只用消隐窗 | ❌ 8 个 64×64 就要 813 µs > 607 µs（**133%**），上限约 6 个 |
| 重叠怎么办 | 脏区**完全重建**（铺背景 → 按 z 序重放簇内全部元素），不是"擦 + 画" |
| z 序怎么保证 | **命令顺序**：CI 队列 FIFO，后发的画在上面 |

### 6.2 ★ 每块缓冲各记一份"上次画在哪"

双缓冲 C/D 由显示端轮流显示，绘制端每帧画"另一块" ⇒ **同一帧里两块缓冲装的不是同一帧的画面**。

如果只维护一份"上次画在哪"（比如统一用"两帧前的位置"），就等于假设"每帧严格交替"——
**这个假设一旦被打断就擦错地方**：同一块连画两次（跳帧、提前退出、整屏重建之后再画）、整屏重建之后起点不再错开。

改成**每块缓冲各记一份**之后，语义变成"**这块缓冲里，这个元素上次画在哪**"，任何时候都成立。
附带好处：**在这块缓冲里没动过的元素，一个命令都不用发**。

### 6.3 每帧三步

```
① 收集脏区
   对每个元素 i（在这块缓冲里动过的）：
       脏区 = rect(它在这块缓冲里的旧位置) ∪ rect(当前位置)，各边留 1 像素
② 合并（MERGE_GAP，默认 32）
   两个矩形相交或间距 < GAP 就并成外接矩形；反复扫到这一轮没有合并为止
   （A 挨着 B、B 挨着 C 但 A 离 C 远 ⇒ 必须多扫几轮才能保证最终互不重叠）
   面积保险：并出来超过整屏 1/4 就放弃这次合并
③ 逐个矩形整块重建
   擦整块 → 补背景（或参考线，在元素【下面】）→ 区内所有元素裁到区内按 z 序重画
```

### 6.4 两条不能破的纪律

| 纪律 | 破了会怎样 |
|---|---|
| 重画必须**裁到当前矩形内** | 元素伸到矩形外的部分会盖掉别处刚补好的内容 ⇒ 屏上竖线被顶穿（透色 / 拖影） |
| 必须**重画全**（区内全部元素），不能只补差集 | 元素每帧被啃掉一圈，几帧就没了 |

有了这两条，**矩形重叠天然安全**：后处理的矩形会把自己整块重建，结果与处理顺序无关；
重叠区最多被多写一两遍（同色，幂等）。

> ★ 等价的安全写法：**只画交集（裁剪）**（现在用的），或"整块画元素 + **外层元素（z 序）、内层簇**"。
> ❌ 不安全的是"整块画元素 + **外层簇、内层元素**"：同一个元素跨两个簇时会被重复绘制，后一次盖掉另一个簇里 z 序更高的元素。
> 仿真实测（小屏穷举对拍，场景 = 大元素横跨两簇 + 高处小元素落在其中一簇内）：外层簇 + 不裁剪 = **100 个错像素**，其余三种写法都是 0。

### 6.5 为什么用"大矩形"而不是"精确的小差集"

一次 DDR 突发的宽度 = 矩形宽度。把擦除拆成"空出来的细边"看起来省字节，实际是灾难：
一条细边只有几十字节 ⇒ **突发次数暴涨**（每行还是一次突发，但每次只搬几十字节）。
**上板实测：拆细边 ⇒ 掉帧 + 闪烁 + 下方拖影更重。**

方向是"**少换向**"而不是"少字节"：DDR3 读写总线要换向（tWTR / tRTW），
大量小突发会把显示取数那条连续读流切碎。合并成大矩形正是往这个方向走。

### 6.6 参数与模板

| 宏 | 默认 | 说明 |
|---|---|---|
| `MERGE_GAP` | 32 | 合并间距。太小 = 命令多，太大 = 白填的行多（极端情况并成整屏反而更糟） |
| `MERGE_PASS_MAX` | 8 | 合并反复扫的轮数上限 |
| `AREA_CAP` | 整屏 / 4 | 面积保险：并出来超过它就不并 |

```
for (c = 0; c < g_cur_n; c++) FILL(back, 簇c, BG);          /* 先铺全部背景 */
for (i = 0; i < ELEM_N; i++)                                 /* ★ 外层: z 序(低→高) */
    for (c = 0; c < g_cur_n; c++)                            /* 内层: 簇 */
        if (元素i ∩ 簇c ≠ ∅) draw(back, 交集, 元素i);        /* ★ 只画交集 */
FENCE;
```

**约束与依赖**

| 项 | 约束 | 原因 |
|---|---|---|
| 元素坐标 | **对齐 4 像素** | 省掉首尾遮头 / 每行多读一拍的浪费（实测小图省 33%） |
| 素材宽度 | **4 的倍数** | 行按 4 像素（一个字）打包；镜像时不会把 padding 翻到行首 |
| 画布 | **双缓冲** | 赛题基础要求；也是"脏区重建"自洽的前提 |
| 帧边界 | 命令在 **FENCE 之前**全部发完；FENCE 后**等翻页真的发生**再进下一帧 | 见 §3 的节拍锁 |
| 软件状态 | 元素表 + **每块缓冲各一份旧位置** + `back` 指示 | 就这些 |

> **历史**：早期版本用"变化集 `g_prev[]` ∪ 本帧变化"的做法（规则 1：重建区 = 本帧变化 ∪ 上一帧的变化集）。
> 它也能对，但**依赖"每帧严格交替"的隐含假设**，且必须存"变化"而不是"重建区"（存错会单调递增、每帧白填一大片）。
> 现在统一改成 §6.2 的"每块缓冲各记一份"，语义更强、不再依赖交替假设。

### 6.7 自检规范（"画对了吗"的硬证据）

**模型**：某像素该是什么颜色 = **z 序最高的、覆盖该点的元素**；没有则是背景。
（有参考线 / HUD 的场景，把它们的层号一并写进期望函数。）

**采样点（每帧都查）**

1. 每个元素的**中心 + 四角**（5 点）—— 查"该画的画了没"；
2. **每个脏区簇的中心 / 边沿** —— 查残留；
3. **两帧前的元素矩形边沿各 1 px** —— 后台里存的正是两帧前那幅，**专抓拖影**；
   ★ 只查第 1 组的话，元素自己在哪都是对的，**拖影一点都查不出来**（上板实测：修复前自检只报 2 个错，而拖影 599/600 帧都在）；
4. 若干纯背景点。

**判据**：`lineBuffer_readPixel(base, px, py) == expect(px, py)` 全部相等，**不一致数 = 0**。
（`readPixel` 返回 `0xRRGGBB`，与 FILL 传的颜色同口径。）

> ⚠️ **调试场景不要缩成"一条水平带 + 只左右走"**：那样 ① 脏区只在 x 方向变化，缺 `prev` 只体现成 4 px 的尾巴；
> ② 元素永不重叠，z 序 + 裁剪那条规则压根没被测到。**缩场景只能缩"数量"，不能缩"维度"**。

### 6.8 验证阶梯

| 层 | 判据 | 状态 |
|---|---|---|
| `tb_m2loopback` / `tb_m3palette` | 单帧写 / 读通路 | ✅ |
| 宿主端算法仿真 `sim/host/dirty_dr_sim.mjs` | 把同一套算法照抄成 JS，用理想图逐像素比对两块缓冲（2000 帧 × 元素 1→32） | ✅ 逐像素 0 错 |
| **上板 P1** | 屏上无残影、重叠遮挡正确；每帧自检不一致 = 0；串口打印命令数 / 脏区面积 / 忙周期 | ✅ 见 `实测数据.md` §5 |
| **上板 P2** | 分屏 CPU / 硬件帧率对比 | ✅ **实测 5 : 60** |
| **上板 P3** | 元素数阶梯加压，记录掉出 60 FPS 的元素数 | ⬜ 待做（对应赛题高阶第 3 条） |

## 7. 上板自测模式（历史留档）

`src/main.c` 里原来用编译期开关 `LB_TEST_MODE` 跑多种自检，现在只保留**初始化自测**，其余模式代码已移除。
需要时按本节贴回 `#if (LB_TEST_MODE == N)` 链（**它是编译期宏，改完必须重编 app**；RTL 没变则不用重新综合）。

### 7.0 保留：初始化自测（读回外设 ID）

一次上电把三条通路全查一遍 —— **APB 槽位译码 / 显示寄存器 / CI 自定义指令**。

| 读什么 | 从哪读 | 期望值 |
|---|---|---|
| `KEY_ID` | APB 槽 0（`0xf8100000`） | `0x4B455930`（"KEY0"） |
| `LINEBUFFER_ID` | 槽 2 显示子块（`0xf8102040`） | `0x4C423031`（"LB01"） |
| `GPU2D_ID` | 槽 2 观测子块（`0xf8102000`） | `0x47503244`（"GP2D"） |
| `CI_gpu2d_checkId()` | 走 **CI 通道** | `0x434D4431`（"CMD1"） |

**判据**：四个都对才继续；任一不对就**停在那里并打印查错方向**
（KEY/ID 读不到 → APB 槽位译码；两个 ID 只有一个对 → `PADDR[6]` 子块选择；CI ID 读到 0 或全 F → CI 线没接上）。

### 7.1 mode 6 —— 边画边显示（CPU 写后台 + 交帧）

分屏，左半固定蓝不动，右半在 A/B 之间红绿交替，每次只交 CPU 那一路。
**判据**：左半始终蓝、右半整体切换、不撕裂。**结论：通过，FPS_CPU ≈ 5 帧/秒**
（半屏 1080p = 3.1 MB/帧，CPU 写 DDR 只有 ~17 MB/s）——
**这条数字本身就是"为什么必须硬件加速"的证据。**

### 7.2 mode 7 —— 加速器最小验证（M1）

`CI_gpu2d_fillRect(LB_FRAME_D, 100, 100, 200, 100, 0x00FF0000)` + 交帧 + 读回四点比对。
**结论**：通过（`(100,100)=(299,199)=0xff0000`、`(300,100)=0x000000`）。
**意义**：块边界一格不差 ⇒ 行距 5760、行首偏移、首尾 WSTRB、4KB 拆笔全部正确。

### 7.3 mode 8 —— M2 回环（DDR 读 → 合成 → 写回 DDR）

源 = 满屏彩条，目的 = 全黑，BLIT 之后抽样逐点比对，**且查目的块左右边界外一列仍是黑**（遮头遮尾没越界）。
目的 x 故意取 `300`（`300*3 = 900`，低 4 位 ≠ 0）—— **专治"首拍不对齐"这类相位 bug**。
**前提**：`Axi_Mux` 的 S2 必须接到 GPU_2D 的读口，否则目的块整块全黑（这个现象本身就是判据）。

### 7.4 mode 9 / 12 —— 带宽实测

5 轮负载（窄块 / 宽块 / 只写不读 / 关显示 …），用寄存器自己算账：
`时间 = ΔBUSY_CYC × 10 ns`、`带宽 = ΔWR_BEATS × 16 / 时间`，并用 CLINT 墙钟交叉验算"自报忙是否诚实"。
mode 12 加测"整屏重画"与"8 个 64×64 脏区 + FENCE"。**结果见 `实测数据.md` §2。**

### 7.5 mode 11 —— 素材源相位

同一张素材画三份，目的 x 落在三种不同**字节相位**上（`x=100 → dst_off=12`、`x=406 → 2`、`x=700 → 4`），
外加一组"同相位不同 y"作对照。**判据**：三份逐点一致、块外仍黑、★ **`RD_BEATS` 增量必须是 0**（素材全在片上）。

> **踩过的坑（写自测代码时）**
> 1. **等完成不要猜延时**：早期用 `bsp_uDelay()` 猜，猜少了读到没画完的图；现在统一 `waitCmdDone(快照 + n)` 且**必须带超时**；
> 2. `waitCmdDone` 的判据写成 `!=` 快照是错的 —— 完成 1 条就被当成"全完成"；
> 3. 每次测完**把显示 enable 开回来**，否则屏留黑，下一轮容易误判成"坏了"；
> 4. 只重下软件时**显示侧 APB 寄存器是保留的**，所以每次先写确定值（`enable(0)` + `setSplit(0)`）再灌图。
