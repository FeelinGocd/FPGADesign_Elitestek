# 第一部分：软件部分（RISC-V 侧）

## 1.1 软件职责总览

- 游戏逻辑（元素坐标/碰撞）；
- 向加速器下发渲染命令（走片上寄存器/FIFO，不占 DDR）；
- 软渲对照模式：CPU 亲自读素材、算、写帧缓冲（慢基线）；
- 帧节奏：接 60Hz VSync 中断，决定翻页/喂命令时机；不关心显示时钟细节。

## 1.2 CPU 的两种角色

| 模式 | CPU 干什么 | 像素活谁干 |
|---|---|---|
| 加速模式（产品） | 游戏逻辑 + 下发命令 | 加速器 |
| 软渲对照（baseline） | 游戏逻辑 + 亲自搬像素 | CPU（必然慢） |

同屏对比 = 同一份命令/场景，两种方式各跑一个半区，屏上实时显示两个 FPS。

## 1.3 帧节奏与 ISR/主循环分工

```
VSync 中断（ISR，µs 级短活）：
  ① 检查各渲染区：上一帧 done？→ 翻页（谁完成谁翻）
  ② 算新一帧游戏逻辑
  ③ 给加速器下发命令（先喂，避免引擎饿着）
  返回
主循环（重活）：
  CPU 软渲自己的半边（慢，可跨 2~3 个 VSync；会被 VSync 打断，正常）
```

- ISR 只放短活；**软渲绝不进 ISR**；
- 规则 1 状态快照隔离：主循环画“本帧开始冻结的状态”，ISR 更新的“下一帧状态”放另一份，禁止边画边改；
- 规则 2 丢帧策略：CPU 画不完就跳中间帧，永远画最新已冻结状态 → FPS 自然下降、画面不乱；
- 规则 3 CPU 软渲 = 慢基线，**不需要突发写**（见 1.6）。

## 1.4 指令模型（下发 / 队列 / 帧完成 / 错误恢复）

- 命令放**片上 FIFO/寄存器**（AXI-Lite/APB），CPU 发命令不占 DDR；
- CPU 把整帧命令塞入队列后立即回来算逻辑，不等单条；每帧只等一次“帧完成”（队列空 + done）；
- 加速器按队列顺序 in-order 执行（后一条可能依赖前一条结果）；
- 错误恢复：加速器把失败事务（地址+命令号）写状态寄存器并拉中断，CPU 查后决定重试/跳过/上报（详见 2.5）。

## 1.5 同屏对比的软件节奏

- 分屏：左半 CPU 软渲（每 2~3 个 VSync 一帧），右半 HW（每 VSync 一帧）；
- 各自独立缓冲对 + 各自 done + 各自翻页 → 快慢解耦；FPS = 各自每秒翻页次数；
- **不能串行**（先等加速器画完再软渲）：两半被锁在同一慢帧率，对比失效；
- CPU 每个 VSync：先喂 HW 命令（µs），主循环剩余时间软渲左半。

## 1.6 CPU 软渲为什么不需要“突发写”

- 软渲半边是故意慢的基线：逐像素写 DDR = 慢，正是演示目的；
- 突发/行缓冲只对“需要 CPU 快”的场景才考虑（cache 行写回自动突发、或行缓冲+搬送器——后者会破坏纯软渲定义）；
- 效率优化优先级：加速器（行突发）> 显示读出（行块预取）> CPU 软渲（不重要）。

# 第二部分：硬件部分（FPGA 侧）

## 2.1 系统链路（硬件视角）

```
BitBlt 加速引擎（硬件 master，in-order，行突发）
   │ AXI Master
   ▼
Axi_Mux / AXI Interconnect（仲裁：显示 > 加速器 > CPU）
   ▼
DDR 帧缓冲 A / B（双缓冲，DDR 只当画布）
   │
   ▼
帧读出器（行块突发预取）→ BRAM 行块缓冲 → HDMI 时序（自走）→ 显示器
```

## 2.2 双缓冲与帧流水线

```
buffer A   [HDMI 扫 F0]        [画 F2         ]    [HDMI 扫 F2]
buffer B   [画 F1     ]        [HDMI 扫 F1    ]    [画 F3     ]
             T0                 T0+16.7ms(翻页)     T0+33ms(翻页)
```

- 渲染与显示并行叠一帧；翻页 = 在 vblank/安全窗口换 front/back 指针（无数据搬运）；
- 慢渲染：没画完就不翻 → 重复扫旧帧 → 掉 FPS 不错画；
- 翻页门控：必须等 back 帧 done，防止把画一半的帧切到前台。

## 2.3 显示链路（自走 + 行块预取）

- HDMI 像素/行/同步时序由硬件计数器自走，0% 依赖 CPU；
- 帧读出器按大行块突发预取进 BRAM（提前 1~2 行块 ping-pong），HDMI 只读 BRAM；
- 显示读给最高（按需紧急）优先级，防止 line buffer underrun；
- 首帧/复位：DDR cal_done 之后先清屏，再启动显示与引擎。

## 2.4 DDR 共享与仲裁机制

- DDR 物理上一次只能服务一个请求；多主共享 = 仲裁器按 **burst 粒度**轮流放行（时间分片），宏观并行；
- AXI 主设备请求（VALID）保持到被放行（READY）→ “没画上”只是多等一拍，不是失败；
- 优先级（推荐）：显示读出（按需紧急）> 加速器 > CPU 软渲；
- 三个访问者全断续（显示按行预取、加速器画完本帧 idle、CPU 每帧总量小）→ 天然有空档，不会饿死；
- 防饿死兜底（任选）：带权轮询槽 / 老化超时提升 / 显示按需紧急；
- 仲裁器 = 一级独立互联逻辑（demo08 `Axi_Mux.v` 或 AXI Interconnect IP），**不是 RISC-V 自带**，接在 CPU+加速器+显示读出与 DDR 之间。

## 2.5 AXI 错误回传与恢复（硬件侧）

- 事务级错误回传：读 `RRESP[1:0]`、写 `BRESP[1:0]`；
- 编码：`OKAY(00)` 成功 / `EXOKAY(01)` 独占成功 / `SLVERR(10)` 从设备错误（DDR 未 cal、ECC、访问被拒）/ `DECERR(11)` 地址无映射；
- 事务独立：一条突发失败只影响该事务，总线无残留，下一条照常；无隐含续传；
- 恢复：引擎靠 ID 定位失败命令，记 `fail_addr`+命令号到状态寄存器并拉错误中断；CPU 查后决定重试/跳过/上报；硬件可自动重试 N 次；
- VALID/READY 是背压/暂停（流控），不是失败，数据不丢。

## 2.6 存储 / 素材（硬件方案）

| 存储 | 内容 |
|---|---|
| BRAM 325KB | 简单元素素材（精灵/瓦片集）、命令 FIFO、显示行块缓冲 |
| DDR 256MB | 帧缓冲 A、帧缓冲 B、（可选）一张大图测试区 |
| Flash / SD（持久化） | 素材源头，开机由 CPU 搬进 DDR/BRAM 后不参与运行时 |

瓦片地图 = 索引表（土/路/水流…）+ 小瓦片集，几十 KB 级，可常驻 BRAM。

## 2.7 写者规则（跨软硬，硬件仲裁落实）

| 场景 | 规则 |
|---|---|
| 区域不重叠 | 可并发写，无先后；DDR 只做带宽仲裁 |
| 区域重叠 | 不能并发；串成有序命令流，或分 pass 固定顺序 |
| 同一 back 被多方写 | 翻页被迫等最慢 → 各自独立缓冲对才解耦 |
| 一帧单写者 | 加速模式 HW 整帧写 / 软渲模式 CPU 整帧写 |

## 附：常见误解速清

| 疑问 | 澄清 |
|---|---|
| HDMI 时序要 CPU 调度吗 | 不需要，硬件自走 |
| 渲染要等 VSync 才开始吗 | 不等；VSync 是翻页点，渲染在两个 VSync 之间整段进行 |
| 画 F2 要等 HDMI 读完 F1 吗 | 不等；翻页后立即画 F2，与 HDMI 读 F1 并行 |
| DDR 一次能多个主设备访问吗 | 物理上一次一个，仲裁按 burst 分时轮流，宏观并行 |
| CPU 抢不到总线怎么办 | AXI 请求挂着等放行，只多等一拍；防饿死靠优先级+轮询槽/老化 |
| 仲裁失败（SLVERR/DECERR） | 事务级回传、独立；记 fail_addr 后由引擎/软件决定重试 |
| 加速器要不要让着 CPU | 反过来：CPU 软渲低优先级让加速器； |
