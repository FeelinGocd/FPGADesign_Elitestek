## 1. SoC 概览

- CPU：**VexRiscv RV32IM + Zicsr + Zifence**，单核（CpuCount=1）。
- **无** A / C / F / D 扩展，**无** MMU / 用户态（supervisor=0）。
- ICache / DCache：**4KB × 1way × 64B/line**。
- CLINT 时钟 = **100 MHz**。
- SoC **内部不含 DDR3 控制器**——DDR 是**外接 AXI4 从口**。

## 3. 总线结构（核心）

VexRiscv 原生总线叫 **BMB（Bus-Master-Bus）**，地址从 `0x0` 起。SoC 用**桥**把 BMB 分成两条总线：

- **bmbToApbBridge** → **APB3**（低速/控制面）
- **bmbToAxiBridge** → **AXI4**（高速/数据面）

| 总线 | 用途 | 挂载 |
|---|---|---|
| **APB3** | 低速外设 / 控制面（`0xf8000000/16MB`） | UART0、SPI0、GPIO0、I2C0、用户 APBSlave0 |
| **AXI4** | 高带宽数据面 | DDR（io_ddrA）、用户 AXI 主窗（AXISlave 0xe1000000）、外部加速器主口 io_ddrMasters_0 |
| **直连 BMB** | — | 片上 RAM(0xf9000000)、PLIC(0xf8c00000)、CLINT(0xf8b00000) |

### 3.1 APB3（控制面，低速）—— `0xf8000000` 起 16MB
- UART0 `0xf8010000`、SPI0 `0xf8014000`、GPIO0 `0xf8015000`、I2C0 `0xf8016000`、**用户 APBSlave0 `0xf8100000`（64KB）**。

### 3.2 AXI4（数据面，高带宽）
- **DDR**：CPU BMB → `bmbToAxiBridge` → **`io_ddrA` AXI 主口** → 外部 DDR3 控制器 AXI 从口。`SYSTEM_DDR_BMB=0x1000`、size `0xe0000000`；AXI 128bit / 8bit ID / 地址低 28 位；DDR3 ≈ 256MB。
- **用户 AXI 主窗（AXISlave）**：`SYSTEM_AXI_A_BMB=0xe1000000`（16MB，32bit）。
- **外部加速器主口 `io_ddrMasters_0`**：SoC 保留一个**外部 AXI 主入口**（32bit），**在 SoC 内部与 CPU 仲裁共享 DDR**——加速器若 32bit 够用可走它免自写汇聚；否则用外部 `Axi_Mux` 汇聚。

## 6. 2D 加速器如何接入 SoC

| 你的东西 | 挂哪条总线 | 地址 / 方式 |
|---|---|---|
| 命令 / 状态 / 描述符寄存器 | **APB3**（用户 APBSlave0） | `0xf8100000` |
| 帧缓冲读写（数据面） | **AXI4 master** | 走 `io_ddrMasters_0` 或外部 `Axi_Mux` 进 DDR |
| 完成中断 | PLIC | `userInterruptA = 16` |

> **控制面走 APB3（0xf8100000），数据面走 AXI4（经 io_ddrMasters_0 / Axi_Mux 共享 DDR）**——对应 `渲染流程.md` 2.1 的 "BitBlt(AXI master) → Axi_Mux → DDR"。

## 7. DDR 多主共享 / 仲裁（CPU 与显示、加速器）

### 7.1 带宽预算（目标 1920×1080@60，需认真对待）
目标显示：**1920×1080@60** —— 像素钟 **148.5 MHz**，行长 2200 / 帧高 1125（HFP=88, HSYNC=44, HBP=148；VFP=4, VSYNC=5, VBP=36，正极性）。
| 主设备 | 需求 | 性质 |
|---|---|---|
| 显示读 | 1920×1080×60 ≈ **373 MB/s**(RGB888) / **497 MB/s**(ARGB8888) | 行块预取，突发，近恒定 |
| 加速器写帧 | 同左（整帧）≈ **373 / 497 MB/s** | 行突发 |
| CPU（读代码/数据） | 有 4KB cache，主要 cache miss，估 **< 100 MB/s** | 突发 |

**显示读（ARGB8888）≈ 497 MB/s**（≈ DDR3 峰值 1.6GB/s 的 31%、实际可用 ~1.2GB/s 的 ~40%）——**足够**，且已是只读活跃区(1920×1080)的最小需求（显示必须读整帧：背景 + 两个方块都要出图）。
**写入侧：同屏对比只渲染 2 个方块（非整屏）**，加速器/CPU 每帧只写该小区域——如 512×512 方块 ≈ 1MB/块，60Hz → **每块 ~63 MB/s**，两块 ~126 MB/s，**写量很小**。
**并发 ≈ 497(读) + ~126(写) ≈ 623 MB/s**，ARGB8888 **完全宽松**；仅每帧整屏重绘才到 995MB/s(≈83%) 的偏紧上限。
> 显示读(全帧)是恒定下限；写入随方块大小增加。稳健优化（按需）：RGB888 减半、行长整对齐(128bit=16B)、bank/tile 友好。

### 7.2 仲裁机制（2026-09-16 修正）

- DDR **单个从口**，多主经 `Axi_Mux` **按 burst 粒度分时**仲裁（宏观并行、微观串行）。
- ⚠️ **修正**：原写"优先级：显示读出 > 加速器 > CPU"——**`Axi_Mux` 不提供这个能力**。
  它只有 `Cfg_Arb_Type` 两档：`0` = 轮询（共享）、`1` = 固定优先级（**S0 最高**）。
  也**没有**带权轮询槽、老化超时提升。
- **实际做法**：用**轮询**（`Cfg_Arb_Type = 0`），靠**缓冲**吸收抖动，不指望仲裁器偏心。
  粗算：三个主都抢时 AR 约 1:1:1 轮流，显示约拿到读通道 **1/3** 的时间；
  而 1080p 显示只需 **23.3%**（见 `地址空间规划.md` §7.2）→ **够用**。
- VALID/READY 流控：未放行只是多等一拍，不是失败、不丢数据。
- 详见 `AXI4FULL解析.md` §18（`Axi_Mux` 数据面硬限制）、§19.3（仲裁能力与现实的差距）。

### 7.3 显示读为何不实时锤 DDR
HDMI 不逐像素读 DDR，而是 **DDR → BRAM 行缓冲 → HDMI**：
- 帧读出器按行块 **AXI 突发预取**进 BRAM（提前 1~2 行块 ping-pong）；
- HDMI 只从 BRAM 读（本地、快、无竞争）；
- 显示对 DDR 是"分块补水"，可被仲裁推迟而不出事（预取跑在前面）。

### 7.4 一帧单写者
- 加速模式：硬件整帧写 back 缓冲；
- 软渲模式：CPU 整帧写；
- 同一 back 不会被多方并发写；分屏对比时各自独立缓冲对。

## 9. 注意事项

1. **访问 DDR 前等 `cal_done`**（DDR 校准完成），否则读垃圾。
2. **`io_ddrA` 是 CPU 唯一的 DDR 出口**；加速器若走 `io_ddrMasters_0` 需确认 SoC 该口已例化/接线。
3. 启动链：复位 → 片上 RAM(0xf9000000) bootloader → 从 SPI Flash(0x380000) 拷 124KB 到 DDR(0x1000) → `userMain()`。
4. CPU 程序/数据与帧缓冲**分 DDR 区**，减少 bank 冲突。
