# 硬件 · 加速器 GPU_2D

> 状态：**已实现并上板验证**（FILL / BLIT / 精灵 / 调色板 / ck / 镜像 / alpha）。
> 命令面 = 自定义指令 **CI**；配置面 = **APB 槽 2**（`0xF8102000`）；数据面 = `Axi_Mux` **S2 读 + S3 写**。
> 系统级约定（四个域 / 时钟 / 复位 / 带宽 / 地址）见 `设计总纲.md`；实测数字见 `实测数据.md`；C 侧 API 见 `软件_驱动与API.md`。
> **§1 是对外协议的唯一定稿** —— 改命令格式只改这一节，同时改 `DDRSource` / `PaletteSource` / `Compositor` 三处解码。

## 1. 命令接口（CI）

### 1.1 物理层：一条 CI 的载荷

| | |
|---|---|
| 通道 | Sapphire SoC 的自定义指令口 `cpu0_customInstruction_*`（CFU），**不占 APB 地址** |
| `function_id` | 10 位 = `{funct7[6:0], funct3[2:0]}` |
| `inputs_0` / `inputs_1` | 各 32 位（一共 64 位载荷） |
| 响应 | 硬件收到就回 `rsp`，`outputs_0` 回固定标识 `"CMD1"` = `0x434D4431`（验通路用） |

**一条命令 = N+1 条 CI**（N = 这条命令画几张图；单图 N=1，合成 N=2）：

| 次序 | `function_id` | `inputs_0` | `inputs_1` |
|---|---|---|---|
| 第 1 条 | **操作类型**（FILL / BLIT…） | `{宽[31:16], 高[15:0]}` | **目的地址** |
| 第 2 条起 | `ARGS`（`3'd7`） | **这张图的源地址**（纯色图传 0） | `{more[31], flags[30:24], 参数[23:0]}` |

最后一条 ARGS（`more=0`）到达才算一条完整命令 —— **命令边界天然存在**，不需要长度字段，也不会有"半截命令"。
★ 字段落位以 `cmd/CIUnpack.v` 与 `code/peripheral/CInstruction/CI_gpu2d.h` 为准（两边逐字对应）。

> ★ **ARGS 的真正作用是把"命令边界"从硬件状态变成数据属性**。
> 若让硬件数数（固定 2 条），一旦丢一条就**永久错位**，整屏跟着乱；现在丢一条只坏一条命令，
> 下一条 `ARGS` 一到就重新对齐。
> ★ 单图两条 CI 的载荷刚好 128 位、7 个字段已经占满，**加不进第 8 个** ⇒ "能算出来的不放"是必须的，
> 不是偷懒：目的行跨距、调色板基址走 APB 配置寄存器；源行跨距由打包规范算出来（字为单位）。

### 1.2 功能号表（`function_id[9:0]`）

| 功能号 | funct7 | funct3 | 命令 | 状态 |
|---|---|---|---|---|
| `10'h000` | 0 | 0 | `NOP` —— 不进队列，译码器直接丢（**全 0 = 什么都不做**，线意外全 0 不会乱画） | ✅ |
| `10'h001` | 0 | 1 | `FILL` 纯色填充 | ✅ |
| `10'h002` | 0 | 2 | `BLIT` 块拷贝 / 精灵 | ✅ |
| `10'h003` | 0 | 3 | `FENCE` 帧结束 | ✅ |
| `10'h004` | 0 | 4 | `BG_ROW` tile 背景一行 | 预留 |
| `10'h005` | 0 | 5 | `BG_FULL` 整屏背景 + 视口偏移 | 预留 |
| `10'h006` | 0 | 6 | `BULK` 批量（描述符数组） | 预留 |
| `10'h007` | 0 | 7 | `ARGS` 参数 CI / 命令结束词 | ✅ |
| `10'h080~` | 1~ | — | 下一组（funct7 换组） | 预留 |

- **一条规律**：每组最后一个取值（`3'b111`）恒为"参数 / 结束词" ⇒ 以后往组里加命令（占 0~6）时终止符永远不用动。
- **内部命令类型取值 = `funct3`（当 `funct7 = 0`）** ⇒ 译码器**零查表**：
  `cmd_type <= function_id[2:0];`。这是**有意的耦合**：两张表合成一张，不会"改一漏一"。
- 一层是 **CI 功能号**（外部协议，10 位），一层是**命令类型**（内部表示，3 位）——
  分开之后下游**完全不认识 CI 协议**，将来命令通道换成 DDR 命令队列只换最外一层。

### 1.3 `flags[7:0]` 位分配（★ 权威表）

| 位 | 名字 | 含义 | 状态 |
|---|---|---|---|
| `[2:0]` | `MODE` | 合成模式：`0` = FILL（不要源）/ `1` = REPLACE（要源）/ `2` = **ALPHA（两路源 + 逐像素混合）** / `3` = **纯色层（颜色合成 REPLACE，见 §1.3.1）** / `4` = **TINT_ALPHA（纯色层 tint + ALPHA 混合）** | ✅ |
| `[3]` | `SRC` | 源类型：`0` = DDR 里的 RGB888 帧 / `1` = 片上 PRAM 调色板素材 | ✅ |
| `[4]` | `CKEN` | **颜色键控使能**：等于键色的像素不写（透明） | ✅ |
| `[5]` | `MX` | **水平镜像**（源行内取样顺序反转） | ✅ |
| `[6]` | `MY` | **垂直镜像**（源行顺序反转） | ✅ |
| `[7]` | **`ROT90`** | **按【列】取样再重新打包**（见 §1.6.1）。★ **单用 = 转置（沿主对角线镜像），不是旋转**：真 90° 必须配 `MX`（顺时针）/ `MY`（逆时针）。★ 它不占 `inputs_1` 的 flags 位，而是搭在 `param[23]` 上 —— 见下面那条"字段按命令模式复用" | ✅ |

`[30:24]` 是原来的 7 位（`[31]` = `more`）；**`[7]` 走 `param[23]`**（`inputs_1[23]`），
所以 `CmdBuffer` 里每条图的 flags 从 7 位加宽到 **8 位**（2026-10-13 改，全链一致）。

> ★★ **字段按命令模式复用（2026-10-13 起，必须照这个读）**：`param[23]` 只有一个，但含义随 MODE 走：
>
> | 命令 | `param[23]` | `param[23:21]` | 谁解释 |
> |---|---|---|---|
> | Sprite / Alpha（`MODE` 0/1/2） | **ROT90** | 无 | `CmdExec` 的旋转地址走法 + `PaletteSource` 的 R_REQ/R_WAIT/R_OUT |
> | 颜色合成（`MODE=3` / `MODE=4` 纯色层那一格） | **tone 的最高位** | `tone`：0 关 / 1 插值 / 2 加光 / 3 乘系数 / 4 正片叠底 | `Compositor` → `imageCombine` |
>
> 两者**不会在同一条命令上同时解释**：旋转条件里明确排除了纯色合成（`flags[2:0] != 3 && != 4`），
> 而 `tone` 只在纯色层（`MODE=3/4`）那一格才被读。⇒ 这不是冲突，是**同一个字节按模式换意思**。
> `MODE=4` 的 3-CI 命令把底图（ROT90 在第 1 格）和 tint（tone 在第 2 格）分开，所以两者可以同时存在。
> 代价：以后要动其中任何一个（比如 `tone` 想加到 5 档以上）**必须重排**，不能只改一边。

> ★ **"模式 → 要哪几路源"不在 `CmdExec` 解码**（2026-10 起）：`CmdExec` 只把 `flags` 原样广播，
> **谁要不要动由每个消费者自己看 `flags[2:0]` 判**。代价是同一张表散在三处，好处是**没有跨模块的"解码结果"线**。

| 谁 | 它自己判什么 | 在哪 |
|---|---|---|
| `DDRSource`（源①） | 这一行要不要我 / 读**源行**还是读**目的行**（alpha 的背景） | `pixel/DDR/DDRSource.v` 的 `my_line` / `bg_rd` |
| `PaletteSource`（源②） | 这一行要不要我 | `pixel/palette/PaletteSource.v` 的 `my_line` |
| `Compositor` | 取哪一路 / 要不要逐像素混合 / `buf_free` 算哪几路 | `factory/Compositor.v` 的 `src_en_of()` |

#### 1.3.1 第 2 层：图片合成 vs 颜色合成（★ 位表唯一定稿）

一条合成命令 = 3 条 CI（命令开始 + 每层一条 ARGS）。**第 1 层永远是 PRAM 素材图**；
**第 2 层有两种模式，由它自己那格的 `flags[2:0]` 区分**：

| 字段 | 模式 A：图片合成（PRAM 特效图） | 模式 B：颜色合成（纯色层） | 模式 C：TINT_ALPHA（MODE=4） |
|---|---|---|---|
| `flags[2:0]` | `1` = REPLACE（这层要源） | **`3`** = 纯色层（REPLACE，不读背景） | **`4`** = 纯色层 + AB（读背景） |
| `flags[3]` | `1`（PRAM 侧） | `1` | `1` |
| `flags[4]` | CKEN（这层要不要抠色） | 同 | 同 |
| `flags[6:5]` | MX / MY 镜像 | 不用（纯色层没有形状） | 不用 |
| `inputs_0[31:0]` | 特效图 PRAM 字地址 | **颜色 `{A[7:0],R[7:0],G[7:0],B[7:0]}`**（ARGB，自带 α） | 同左 |
| `param[11:0]` | 素材行跨距（字） | 0 | 0 |
| `param[19:12]` | 0（填非 0 = 给这层也调色） | **强度 `strength`（0~255）** | 同左 |
| `param[23:21]` | 0 | **色调模式 `tint`**：`0`=关 / `1`=插值染色 / `2`=加光 / `3`=乘系数 / `4`=正片叠底 | 同左 |
| `param[20]` | 0 | **`below`**：`0` = 特效层在上（默认）/ `1` = 在下 | 同左 |

- ★ 颜色走 `inputs_0`（32 位整用，ARGB）；`param` 24 位切成 **12 跨距 + 8 强度 + 3 色调 + 1 上下**，正好用满。
- ★ **tint 的系数不进命令**：命令只给"模式号 + 强度"；要染色就把颜色填在 `inputs_0` 里。
- ★ 纯色层的出口掩码**继承下层（图一 / ck 之后）的掩码** ⇒ 颜色不会糊到图形外面。
- ★ `tint` 作用在 **`imageCombine` 逐字节那一级**（在 `alphaBlending` 之前，见 §5.6）：
  作用对象是**缓冲里那张图（下层）的字节** ⇒ 背景（读回来的目的像素）不受影响；
  也正因为不在 AB 里，**REPLACE 这类不走 AB 的命令一样能用 tint**。
- ★ `param[20]`（`below`）现在**恒按 0 用**（特效层在上）；这一位已经实现，但还没有命令用到它。

### 1.4 各命令的语义

| 命令 | 源 | 目的 | 语义 |
|---|---|---|---|
| `FILL` | 不用（`color` 就是填充色） | 帧缓存 | 把 `w×h` 的矩形刷成 `color` |
| `BLIT` | 地址 = 第 2 条起 `ARGS` 的 `inputs_0` | 地址 = 第 1 条 `inputs_1` | 把源按 `w×h` 搬到目的；源是 DDR 时必须与目的**同跨距** |
| `BLIT + SRC=1`（精灵） | PRAM 里的**字**偏移 | 帧缓存 | 源是索引图 + 调色板，**全程不读 DDR**；`color` 字段改为放**源行跨距（字）** |
| `BLIT + MODE=2`（**alpha 混合**） | PRAM 精灵（前景，带 α）**+ 目的自己**（背景） | 帧缓存 | 按调色板里那一项的 α **逐像素混到背景上**（§5.3） |
| `BLIT + MODE=4`（**tint + alpha**） | PRAM 精灵（base，带 α）**+ 纯色层 tint + 目的自己** | 帧缓存 | `imageCombine` 先给 base 上色，`alphaBlending` 再用 base 的 α 和背景混合（§5.6） |
| `FENCE` | — | — | 等前面所有绘制落盘 → 置 `DONE_ACC`（显示侧在帧边界翻页） |

**三条铁律**（C 侧 API 已经封好，但写文档要写清）：

1. **硬件只认地址不认坐标**：目的地址 = 帧缓存基址 + `y × 行字节数` + `x × 3`，**软件算**；
2. **行字节数 = 画布宽度**（全屏 5760 / 分屏 2880），**不是矩形宽**；
3. **地址必须 < `0x1000_0000`**：`Axi_Mux` 只透传 28 位，超了会写飞。

### 1.5 alpha 命令怎么发（`MODE=2`）

命令形状和精灵 `BLIT` **完全一样**，只把 `MODE` 从 `1` 改成 `2`、`SRC` 置 1：

```
第 1 条 CI : function_id = BLIT(0x2)   inputs_0 = {宽, 高}   inputs_1 = 目的地址
第 2 条 CI : ARGS  inputs_0 = 精灵在 PRAM 里的字偏移   inputs_1 = {more, flags, color}
                  flags[2:0] = 3'd2   ← MODE_ALPHA
                  flags[3]   = 1      ← 源是 PRAM 精灵（alpha 只支持这条路径）
                  flags[4]   = ck 开关（可以和 alpha 同开，两个掩码相与）
                  flags[6:5] = MX / MY（照旧可用）
                  color[23:0]= 源行跨距（字）
```

- **背景不用给**：硬件把**这条命令要写的那块矩形**读回来当背景（源① 的行地址 = 目的行地址）；
- α **不在命令里**：它是**调色板每一项的高 8 位**（一项 = `AARRGGBB`）⇒ "一个索引 = 一种 (颜色, α)"；
- ⚠️ **别拿它刷整屏**：读回量 = 矩形那一段；整屏读回会把 DDR 读带宽吃满。

### 1.6 X / Y 镜像（`flags[6:5]`）

| 位 | 名字 | =0 | =1 |
|---|---|---|---|
| `flags[5]` | `MX` | 源行**从左往右**取 | 源行**从右往左**取（水平翻转） |
| `flags[6]` | `MY` | 源行**从上往下** | 源行**从下往上**（垂直翻转） |

> ★ 这张表是**不旋转**时的取法。开了 `ROT90` 之后 `MX`/`MY` 仍然表示「结果左右翻 / 上下翻」，
> 但实现换成了「选列号起点 / 选列扫描方向」—— 见 §1.6.1 那张 8 组合表，别把这里的「改取样顺序」套到旋转上。

**语义三条（别读串）**

1. **只改"源怎么取"，不改"画到哪"**：目的地址、`w`、`h` 全部不变，画出来的矩形位置尺寸和不开镜像**完全一样**；
2. **镜像是在"要画的那一段"内部翻**（宽 = `w`），**不是**"整张素材翻了再裁" ⇒ 源地址的约定一个字不用改
   （还是"这一段在未镜像时的左边缘"）；
3. **和 ck / 掩码互不干扰**：掩码跟着**像素**走，镜像只改像素的**取值顺序** ⇒ 透明像素镜像之后还是透明。

**实现方式（分工：指令流水算地址，取出器只管"往回走"）**

| 位 | 在哪实现 | 怎么实现 |
|---|---|---|
| **MX** | `CmdExec` 算起点 + `PaletteSource` 递减 + `PaletteDecoder` 字内反序 | 广播的源地址改成 `行首 + ceil(w/4) − 1`（**行尾那个字**）；取出器每读一个字 **−1**；字内 4 个索引**反序** |
| **MY** | **只改 `CmdExec`** | 取命令那一拍把源地址推到 `cmd_src + (h−1)×stride`（**最后一行**），之后每行 **−stride**；目的地址照旧正向推进 |

**为什么 MY 两个源通吃、MX 只通吃 PRAM**：MY 只改"哪一行的地址"，而源只认"这一行的起始地址" ⇒ DDR 源也吃得到；
MX 要"行内倒着取"，而 DDR 源的行缓冲是 **FIFO 型 ping-pong**（只有顺序读口、没有地址口），要支持得换成可寻址 RAM，不做。

**约束（写素材时要守）**

| # | 约束 | 为什么 |
|---|---|---|
| 1 | **MX 要求 `w` 是 4 的倍数** | 一个索引字 = 4 个像素。`w` 不是 4 的倍数时，行尾那个 padding 像素（索引 0 = 白）在倒读时会**跑到最前面**，整行错 1~3 像素 |
| 2 | 裁剪（`w` < 素材宽）时，镜像是**在那一段内部**翻 | 源地址给的是那一段的左边缘（约定不变），"先裁哪一段"由软件决定 |
| 3 | DDR 源目前不支持 MX | 见上一条 |

**照这个用就不会错**（老 `demo_anim.c` 的 `draw_sprite()` 是这么写的；★ 现在游戏 demo 的素材宽本来就取 4 的倍数 ⇒ 不需要这个补白技巧）：

```
wpad = stride_word * 4;            /* 素材行按 4 对齐后的宽度：本工程是 64 / 68 */
pad  = wpad - 素材真实宽;           /* 行尾补了几个白像素：1 / 3                */

画:            w  = wpad;          /* 必须 4 的倍数 */
               dx = flip ? (x - pad) : x;   /* 镜像后白像素跑到左边，dx 减掉它 */
擦除 / 脏区框:  从 x - 3 起、宽 71（= 68 + 3）、高取两帧里较高的那个
```

补出来的白像素被 ck 抠掉（看不见），`dx − pad` 保证**镜像前后图形位置严格对称**。

C 侧 API：

```
#define GPU2D_FLIP_X   0x1u   /* MX 水平 */
#define GPU2D_FLIP_Y   0x2u   /* MY 垂直；0 = 不镜像（老行为） */

CI_gpu2d_spriteFlip  (asset_base, stride, dst_fb, dx, dy, w, h, flip);
CI_gpu2d_spriteFlipCK(asset_base, stride, dst_fb, dx, dy, w, h, flip);   /* 人物左右跑就是这一条 */
```

**★ 镜像位是"按格"的（一份命令里每张图各管各的）**

一条合成命令有 2 格 flags，`flags[6:5]` 只在**写它的那一格**上生效：
想让"底图"跟着角色朝向翻面，就写在**底图那一格**（`CI_gpu2d_combineTint()` 的 `base_flags`）；
纯色层没有形状，那一格写了也没用。典型例子是"撞墙闪红"：闪红那几帧也得保持同一个朝向，
否则看着像"撞一下就转过身了"（`tb_m2loopback` 第九、第十段就是照这条命令建的）。

★ 踩过的坑（2026-10，端到端仿真抓到）：MX 命令的**第一行**曾经不做字内反序 ——
因为"这一趟是第几格"（`dec_flags`）原来只看 `pass_r`，而上一条命令若是两张图的命令，
`pass_r` 还是 1 ⇒ 第一行选到了空的第 2 格。修法见 §5.5 那条"选趟不能只看 pass_r"。

#### 1.6.1 按列取样（`ROT90`）—— 单用是「转置」，不是「90° 旋转」

**一句话**：镜像只改"取样顺序"，`ROT90` **换取样方向**（按【列】取、再重新打包成一拍 4 像素）。
2026-10-13 落地，走 `flags[7]`（由 `param[23]` 搭上来，见 §1.3 那条"字段按命令模式复用"）。

★ **`ROT90` 单用的映射是 `out(x,y) = src(y,x)`（沿主对角线镜像 = 转置）** —— 这正是
`tb_m2loopback` 第 11 段逐字节验过的那一条（见本节末尾"验证"）。**它不是 90° 旋转**：
右箭头转置之后虽然也朝下，但**手性反了**，用在门、文字、斜接角这类不对称的图上，一眼就能看出来。
真正的 90° 旋转必须**和镜像位组合**：旋转时 `MX`/`MY` 改的是"这一列从下往上取还是从上往下取"
和"拿第几列当第一行"，效果等于**对结果再翻一次** ⇒ 8 种二面体变换全部可达：

| `ROT90` | `MX` | `MY` | 映射（`W`/`H` = 素材宽高，转置后输出 `H×W`） | 就是 |
|---|---|---|---|---|
| 0 | 0 | 0 | `out(x,y) = src(x, y)` | 原样 |
| 0 | 1 | 0 | `out(x,y) = src(W-1-x, y)` | 左右翻 |
| 0 | 0 | 1 | `out(x,y) = src(x, H-1-y)` | 上下翻 |
| 0 | 1 | 1 | `out(x,y) = src(W-1-x, H-1-y)` | 180° |
| 1 | 0 | 0 | `out(x,y) = src(y, x)` | **转置**（沿主对角线镜像）|
| 1 | 1 | 0 | `out(x,y) = src(y, H-1-x)` | **顺时针 90°** |
| 1 | 0 | 1 | `out(x,y) = src(W-1-y, x)` | **逆时针 90°** |
| 1 | 1 | 1 | `out(x,y) = src(W-1-y, H-1-x)` | 反对角镜像 |

⇒ 写软件只需记两行：**顺时针 90° = `ROT90 | FLIP_X`**、**逆时针 90° = `ROT90 | FLIP_Y`**。
裸 `ROT90` 只配"本来就左右/上下对称的图"（圆点子弹、条纹木纹），**别拿它当旋转用**。

**为什么不能只用 MX/MY 拼**：MX/MY 只改取样顺序，没法把"按行取"变成"按列取"；
`ROT90` 把取样方向换掉之后，MX/MY 才变成"选方向的两位"（见上表）。
⇒ 这是**源侧数据通路**上实打实的一档新功能，不是软件能等效的。

**地址怎么走（★ 关键约定）**：旋转时源地址的高 2 位**不再是地址的一部分**，而是"这一拍取哪一列"：

| 字段 | 含义 |
|---|---|
| `addr[31:30]` | **列号 0~3**（一个字 = 4 个像素 = 4 列） |
| `addr[29:0]` | 字地址 |

`CmdExec` 里三个函数负责按列走：`rot_col_last_addr()`（本行最后一列的地址）、
`rot_col_next_addr()` / `rot_col_prev_addr()`（列 ±1，列满 4 进 1 个字）。

**取出器怎么取（`PaletteSource`）**：每趟旋转先经 `R_MUL → R_ADDR` 准备起点，然后循环 `R_REQ → R_WAIT → R_OUT`：

| 状态 | 干什么 |
|---|---|
| `R_MUL` | 将锁存的 `(w−1)×stride` 乘积与输出总拍数寄存，初始化像素剩余标志 |
| `R_ADDR` | 按 MX 将锁存的基址与乘积相加，寄存起始字地址，初始化输出拍数的剩余标志；准备阶段不发 RAM 请求 |
| `R_REQ` | 发一个字地址（这一列当前落在哪个字） |
| `R_WAIT` | 收字 → **只抽 1 个索引**（`index_data[rot_lane_r*8 +: 8]`）→ 攒 4 个凑成一拍 |
| `R_OUT` | 把攒好的字直接喂 `PaletteDecoder`（绕开素材 RAM 的正常出口） |

`rot_total_beats = ceil(needed_bytes/12)` 拍之后这一行结束；**合成那一路（第 2 趟）同样支持**。
宽度和两趟源地址在行任务接收时锁存；第 2 趟的旋转列号与基址也必须取锁存值，不能使用已被 `CmdExec` 预推进的实时地址端口。
旋转连续预取只使用提前寄存的“下一像素/下一输出拍是否存在”标志；宽计数器的增量和比较不再直接串入素材 RAM 读使能。标志分别随真实取样与 Decoder 交包握手更新，反压时保持；零/单像素及行尾补零的边界由初始标志和剩余标志共同约束，不额外增加取样拍。
★ 旋转生效时 `dec_flags` 会把 **MX 位屏蔽掉** —— 屏蔽的只是 `PaletteDecoder` 的**字内反序**
（旋转按列取样，字内反序没有意义）；**MX 本身仍然生效**：`PaletteSource` 拿它选"这一列从下往上取"
（起点 `+ (w−1)×stride`、之后每拍 `−stride`）⇒ 结果等于**左右翻**。
`MY` 则由 `CmdExec` 的 `rot_col_last_addr()` / `rot_col_prev_addr()` 改**列号起点** ⇒ 结果**上下翻**。
所以"旋转时屏蔽 MX"只对"字内反序"成立，**别理解成 MX 无效**。

**软件怎么用**（`CI_gpu2d.h`）：

```c
#define GPU2D_ROT90  0x4u   /* 和 FLIP_X/FLIP_Y 放同一个 extra/flip 字段里（不是 flags 位）*/
CI_gpu2d_spriteFlipCK(base, stride, fb, x, y, w, h, GPU2D_ROT90);                 /* 转置（不是旋转！）*/
CI_gpu2d_spriteFlipCK(base, stride, fb, x, y, w, h, GPU2D_ROT90 | GPU2D_FLIP_X);  /* 顺时针 90° */
CI_gpu2d_spriteFlipCK(base, stride, fb, x, y, w, h, GPU2D_ROT90 | GPU2D_FLIP_Y);  /* 逆时针 90° */
```

驱动做两件事：① `param[23] = 1`；② **把命令的 `w/h` 交换**（转完宽高互换）。

**两条路并存，别混**：

| 路径 | 做法 | 什么时候用 |
|---|---|---|
| **硬件 ROT90** | 一份素材 + `param[23]` ⇒ 硬件按列取样 | 要现场转、或者不想多存一份素材（**游戏 demo 的上下子弹走这条**）|
| **软件预生成** | `pic2pram.py` 打包时转 90° 存成另一张图，命令直接指它 | 方向固定、QPS 敏感（省掉 1/4 吞吐的代价）|

**验证（2026-10-17）**：`tb_m2loopback` 第 11 段用 88×56 的矩形逐字节比对，
四种候选转置映射里**只有 `out(x,y) = src(y,x)` 误差为 0**（其余三种各错约 1 万字节），
这一条就是 §1.6.1 那套地址走法的金标准；上板子弹上下方向正常。
⇒ 它验的是**裸 `ROT90` = 转置**；`ROT90|MX`（顺时针）/ `ROT90|MY`（逆时针）这两种组合
**还没有逐字节用例**（2026-10-24 记，见 §7 遗留清单）。补 TB 时用例要带方向性（箭头 / 门），
**别用圆点子弹** —— 对称的图转置和旋转长得一样，验不出来。

> ★ 吞吐：旋转时**一拍只能取 1 个索引**（要攒 4 个才够一拍像素），所以**同样的精灵比不转慢约 4 倍**。
> 只适合小图（子弹 / 图标），别拿它转整屏角色。
### 1.7 变长命令（`more` 位）

`ARGS` 的 `inputs_1[31]` = `more`：

- `more = 0`：本命令到此为止（**当前恒 0**，所以"看到 `3'd7` 就是命令结束"）；
- `more = 1`：后面还有参数 CI，可以连续推多条 `ARGS`。

将来 `BG_ROW` / `BG_FULL` / `BULK` 都要靠它带 3~5 条参数，**格式不用改，只是多推几条**。
也就是说：`3'd7` 表达"这是一条参数"，`more` 表达"还有没有下一条"。

## 2. 为什么是这套命令（推导，答辩会问）

### 2.1 硬件最小要能干什么

硬件的本质能力是"**把一块矩形变成确定的内容**"。内容的来源穷举只有两种：

| 来源 | 例子 | 命令 |
|---|---|---|
| **常量**（颜色是 CPU 直接给的数） | 清屏、色块、血条、底色 | **FILL** |
| **另一块内存**（内容已经存在） | 背景 tile、精灵、整张大图 | **BLIT** |

**没有第三种。** 少任何一个都画不出东西；**再多就没必要** —— "画圆""画线"这类**能用矩形组合出来的东西不该进硬件**
（软件拆成小矩形即可），否则每加一条命令 = 多一套状态机 + 一整套验证。
这正是赛题定的分工：**"RISC-V 仅负责高层逻辑与下发指令，由 FPGA 完成底层像素的高速搬运"**。

### 2.2 一条 CI 装不下 ⇒ 分两条，第二条自己声明是尾巴

一条绘图命令至少要 `源(32) + 目的(32) + 宽(16) + 高(16) = 96 位`，而一条 CI 只有 64 位载荷。

第二条为什么要给功能号（`ARGS`）？因为它实际承担的是**命令边界标记**：

| 做法 | 后果 |
|---|---|
| 硬件**数数**（约定一条命令固定 2 条 CI） | ① 命令一变长就得改计数逻辑；② **丢一条就永久错位**，整屏跟着乱 |
| 第二条**自己声明**"我是尾巴"（ARGS） | ① 译码器不数数、不关心长度；② 丢一条只坏一条命令，下一条 ARGS 一到就重新对齐 |

### 2.3 硬件怎么知道"这一帧画完了" ⇒ FENCE

**推不出来。** 两个想当然的判断都错：

| 想当然 | 为什么错 |
|---|---|
| "队列空了 = 画完了" | 队列空只是**瞬时状态**：CPU 在两条命令之间算一下坐标，队列就是空的 ⇒ 会**每两条命令交一次帧**，屏幕疯狂闪烁 |
| "命令都发下去了 = 写完了" | 命令发下去只代表搬运**开始**，DDR 写响应可能还在路上 ⇒ 显示翻到的可能是**还没写完的缓冲** |

根子在于硬件**区分不了**"这一帧只有 3 条命令、推完了"和"还有 10 条没推完、CPU 正在算"。
所以要一个**显式事件**（FENCE）："从现在起不会再有新命令了，把剩下的写做完就可以交帧。"

> **为什么不能改用 APB 寄存器当帧边界**：**CI 和 APB 是两条独立通道，它们之间没有顺序保证** ——
> APB 写可能在 CI 命令还没执行完时就到了 ⇒ 帧边界提前 ⇒ 撕裂。**命令必须走同一条通道，顺序才有保证。**

FENCE 的连带作用：① 交帧（防撕裂，主要目的）；② 帧率统计（每秒几个 done = FPS）；
③ 将来：调色板只在帧边界切换等。

> 一句话：**渲染硬件本身没有"帧"的概念**，它只是把命令一条条执行掉。
> 是**双缓冲 + 显示同步**逼着它必须知道帧边界，而帧边界在命令流里得有东西表示 —— 那就是 FENCE。

`NOP` 没有功能上的必要，纯粹为**调试**（测 CI 通道、测队列深度、占位），砍掉不影响任何功能。

### 2.4 CI 通道实测结论（IP 已生成，端口已确认）

**只有 CUSTOM0 能发命令** —— 这是硬件解码矩阵定死的：SoC 生成的合法指令矩阵里只有 opcode `0x0B` 被解出来。

| 宏 | opcode | 结论 |
|---|---|---|
| `cfu_push` / `cfu_pop` | CUSTOM1 `0x2B` / CUSTOM2 `0x5B` | **非法指令**，CPU 根本不认 —— 发出去就死在那儿 |
| `cfu_type_R(func3, funct7, rs1, rs2)` | CUSTOM0 `0x0B` | ✅ 唯一可用。语义是**发 + 等结果** |

> **上板实锤**：用 `cfu_push` 的固件只打出 `A:` 就没了；换 `cfu_type_R` 后 `id=0x434d4431` 正常返回。
> 综合器剪网表也是旁证：`project.map.v` 里 `cpu0_ci_cmd_valid` / `inputs_1` / `outputs_0` 出现 **0 次**。
> 上板扫过 `func3 = 0/1/2/3/7` 全部返回 `0x434D4431` ⇒ 功能号 10 位确实都可用。

**端口（8 根）**：`cmd_valid / cmd_ready / function_id[9:0] / inputs_0[31:0] / inputs_1[31:0] / rsp_valid / rsp_ready / outputs_0[31:0]`。

**握手是阻塞式的**（`cmd_valid` 保持到 `cmd_ready`；**`rsp_valid` 不给，写回级 stall，整条流水线停**）
⇒ 两条硬性要求：

1. **CI 从端收到命令就尽快回 `rsp`**（1~2 拍），把绘制丢后台。否则 CPU 被绘制时间拖着，"CPU vs 硬件帧率对比"会失真；
2. **不能用 CI 查"画完了吗"**（那会把 CPU 卡到画完）。帧完成状态走 `acc_frame_done` / APB 状态位。

> ★ `cfu_type_R` 的宏把 `func3` / `funct7` 拼进 asm 的 `.word` 表达式 ⇒ 调用点**只能写字面量**：
> **不能带 `u` 后缀**（`0x1u` 会拼成非法表达式），**也不能传宏名**。
> 头文件里 `#define GPU2D_FID_FILL 0x001` 故意不带 `u` 就是为了这个。
> 附带好处：`cmd_ready` 本身就是反压手段 —— 命令 FIFO 满就拉低，CPU 自然等。

## 3. 一条命令的生命周期

### 3.1 取命令

后级只有一个判断：**命令队列空不空**。

```
cmd_rd_en = (state == S_IDLE) && !cmd_empty
```

忙碌期间不取，队列满 → 反压 → 译码器停 → CI 从端 `cmd_ready` 拉低 → CPU 自然等。

### 3.2 按 `op` 分派（只在取命令时判一次，不在每行里判）

| `op` | 含义 | 处理方式 |
|---|---|---|
| `3'd1` | **FILL** | **不发读命令**；内部直接产生"固定颜色"的像素流 → 打包 → 写 |
| `3'd2` | **BLIT** | 发读命令 → 收源数据 → 取样 → 查调色板（若 PRAM）→ 合成 → 打包 → 写 |
| `3'd3` | **FENCE** | 不搬任何东西；等写响应收齐 → 上报"帧尾" |
| （NOP 不进队列） | — | — |

### 3.3 展开成逐行搬运

一条命令 = **高（h）行**，每行 **宽（w）个像素**：

```
第 y 行（y = 0 … h-1）:
    目的行地址 = 目的地址 + y × 目的行跨距     ← 跨距来自 APB 配置寄存器
    源行地址   = 源地址   + y × 源行跨距       ← FILL 时不用；PRAM 源时跨距按【字】给
    这一行像素数 = 宽
    → 交给"行引擎"，等它回 line_done
```

> **实现细节**：行地址用**累加**（每完成一行 `行地址 += 跨距`），**不用乘法器**。

### 3.4 一行之内发生什么

```
                    ┌── FILL ──▶ 固定颜色 ──────────────────┐
行请求 ──▶ 行引擎 ──┤  (MODE 决定)                          ├──▶ 合成 ──▶ 打包 ──▶ 写 ──▶ DDR
                    └── REPLACE/ALPHA ──▶ 源① / 源② ──▶ 查表 ─┘
```

**几种 `op` 共用后半段（合成 + 打包 + 写），只在"像素从哪来"处分叉** —— 不用做多条独立通路。

### 3.5 判收工

```
一条绘图命令收工 = 第 h 行都搬完  且  写引擎的写响应全部回来
```

后半句**不能省**：写命令发出去 ≠ 写完成。不等响应就报"画完了"，`acc_frame_done` 会**早响**，
显示翻页时数据可能还没落进 DDR。

### 3.6 状态机（4 个状态）

```
S_IDLE   看队列空不空 → 取出一条命令，锁存为"当前命令"
           op = FENCE → S_FENCE ；其他 → y ← 0，进 S_LINE
S_LINE   发 line_req(y)，等 line_done；y ← y+1；y == h ? → S_DONE
S_DONE   等写引擎 idle（写响应全回来）→ 命令计数 +1 → S_IDLE
S_FENCE  等写引擎 idle + 行引擎空闲 → 发 frame_done_req（单拍）→ S_IDLE
```

### 3.7 命令字段 → 谁消费

| 命令字段 | 谁用 | 拿来干什么 |
|---|---|---|
| `op` | `CmdExec` | **分派**：走哪条通路、是不是帧结束 |
| 源地址 | 地址生成（BLIT） | 算每行的源起始地址（PRAM 时是字偏移） |
| 目的地址 | 地址生成 + `DDRSource`（alpha 的背景） | 算每行的目的起始地址 |
| 宽 | 地址生成 + 打包器 | 一行像素数 → 一行字节数 → 拆几笔、发几拍 |
| 高 | `CmdExec` | **推进多少行**（唯一的"循环次数"） |
| `flags` | 各源 / 合成器 / 混合器 | 源类型、模式、ck、镜像 |
| 颜色 / 跨距 | 打包器（FILL）/ 源侧（PRAM） | 填充色；PRAM 素材的行跨距（**字**） |

> **一句话**：`op` 决定走哪条路，`宽 × 高` 决定工作量，`源 / 目的 / 跨距` 决定搬到哪，
> `flags / 颜色` 决定像素长什么样。后级不"理解"命令的语义，只是把这几个数喂给下游模块。

## 4. 数据通路

### 4.1 结构

```
CI → CmdChannel → 行任务 ─┬→ DDRSource ──────┐
                          ├→ PaletteSource ──┼→ Compositor → DDRPacker → WriteController → AXIMastersHandler → DDR
                          └─（填充色旁路）────┘        └─ line_done ─→ CmdExec
```

| 模块 | 干什么 |
|---|---|
| `pixel/DDR/DDRSource` | 收行任务 → 按拆笔公式发 AR → 读回字节交给 `DDRUnpacker` → 写进自己的 ping-pong → 96b 像素流 |
| `pixel/DDR/DDRUnpacker` | 128b 拍流 → 每拍 4 个 RGB888（字节累加器 + 相位对齐 + 丢头 / 补头） |
| `pixel/palette/PaletteRAM` | 索引 RAM（`RAM_ADDRESS_WIDTH` 位地址、32 位字 = 4 索引 / 拍）；读口是规范的 valid/ready 握手 |
| `pixel/palette/PaletteLUT` | 256 × 32 bit 调色板（BRAM，一项 = `AARRGGBB`） |
| `pixel/palette/PaletteDecoder` | 两槽寄存索引队列 → LUT → RGB888 与 α 旁路；本地队列占用决定入口 ready，busy 包含队列和 LUT |
| `pixel/palette/PaletteSource` | 收行任务 → 逐行取索引 → 查表 → 96b 像素流 + α 旁路 + ck 掩码（出口契约与 `DDRSource` 一致） |
| `factory/Compositor` | 自己按 `flags[2:0]` 选源 → （两路同时用则逐像素混合）→ 96b 输出 + 字节掩码 |
| `factory/DDRPacker` | 96b（12 B）攒成 128b（16 B）一拍；**行首把字节计数预置成 `dst_off`** |
| `factory/WriteController` | 一行 → 若干笔 AW；首尾 WSTRB 遮头遮尾；发 `line_done` |
| `interface/AXIMastersHandler` | AXI 读主（S2）+ 写主（S3） |

### 4.2 三个关键设计点

1. **拆笔**：`n = min(256, page_beats, left)`，而 `page_beats` 必须用**清低 4 位后**的地址算
   （`(4096-off)>>4` 整除会得 0；写侧那次就是它把 `Axi_Mux` 的 W 通道锁死，见 `设计总纲.md` §8.4）。
2. **只对齐到源块自己的字节 0**：`shift = src_off`；开头丢掉 shift 个读回字节。
3. **读回拍数** = `ceil((src_off + 3w + 16) / 16)` —— 恒 ≥ 写侧拍数，多出来的字丢掉即可，**不需要额外补读**。

**支点**：每路的出口流都是**像素对齐**的（一拍 = 4 个整像素），"摆进目的 16 字节拍"统一在 `DDRPacker` 做
⇒ 合成器看到的多路流天然同相位、逐拍 lockstep 配对，**不需要任何跨 bank 重排逻辑**。

### 4.3 ★ 拍对齐下沉到 `DDRPacker`（关键修正）

**改之前的毛病**：写侧的字节流是从**目的 16 字节对齐基址**开始的，开头 `dst_off = dst_addr[3:0]` 个字节被 WSTRB 遮掉
⇒ 流的第 `dst_off` 个字节必须是本行第 0 个像素的 B。这件事原先**由每个源各自做**
（PRAM 源用 36 字节窗口补哑字节；DDR 源用 `shift = src_off − dst_off`）——
结果是**打包的事混进了"源的相位对齐"** ⇒ 合成器看到的一拍 12 字节**不是整像素**（`dst_off` 不是 3 的倍数时跨 5 个像素）
⇒ **α（一个像素一个）就配不上了**。

**改法**：

| 环节 | 改后 |
|---|---|
| `PaletteDecoder` | **删掉 36 字节窗口和掩码窗口移位** —— 它唯一的活就是补哑字节。输出 = LUT 的 4 个像素，整拍 |
| `DDRSource` | `shift = line_src_addr[3:0]`（**去掉 `− line_dst_addr[3:0]`**）—— 只把读流对齐到源块自己的字节 0 |
| `DDRPacker` | **行首 `cnt_byte <= dst_off`**（新增输入 `dst_off[3:0]`） |
| `Factory` | 把 `line_dst_addr[3:0]` 传给 `DDRPacker` |
| `Compositor` | 两路同时用 + 逐像素混合 |

**等价性**：源侧按 `src_off` 对齐 + 打包级补 `dst_off` = 原来的 `src_off − dst_off`（BLIT 同样成立）。

**收益**：合成器看到的一拍 = **4 个整像素**；α 一拍正好 4 个；"谁负责拍对齐"从"每个源各做一遍"变成**一处**。

### 4.4 ★ 常数色【不做】相位轮转（上板踩过，别再加回来）

下沉之前，常数色（FILL）是按**拍网格**铺的：`Compositor` 不知道目的在拍内的字节偏移，
所以它按 `dst_off mod 3` **把颜色轮转一下**去迁就那个网格。
下沉之后 `DDRPacker` 行首已经做了这件事 ⇒ 那段轮转成了**双份补偿**，块里的颜色被多转一次（R/B 互换）。

| | 表现 |
|---|---|
| 为什么 TB 没抓到 | TB 只比"两遍之间一致 + 掩码"，**从来没查过常数色的绝对值**；而且只在 `dst_off mod 3 != 0` 时错 |
| 上板表现 | **方块颜色随位置变**（x 一变相位就变）、**擦除后留彩色残影**（擦背景那次 FILL 也被转） |
| 修法 | `Compositor` 不再看目的地址的相位，`fill_data = {4{color_r}}` 原样铺；`phase_r` / `mod3()` 全删，连 `line_dst_addr` 这个端口都不要了 |
| 新防线 | `Factory_ck_tb` 新增 `chk_fill_abs`：**`dst_off` 0~15 全扫、逐字节比绝对颜色**；`tb_m2loopback` 的 FILL 段随之从 FAIL 变 PASS |

> ★ 教训：**只看"两遍一致 + 掩码"的 TB 查不出绝对值错误**。凡是"某个字段被解释成别的东西"的改动，
> 都要有一条"逐字节比绝对内容"的用例。

## 5. 合成、混合与掩码通路

### 5.1 选路（`Compositor`）

```
src_en_of(flags[2:0], flags[3]):
    0 = FILL        → 00  不要源，出常数色
    1 = REPLACE     → 01（flags[3]=0，DDR 源）或 10（flags[3]=1，PRAM 源）
    2 = ALPHA       → 11  两路同时用：源② 前景(带 α) + 源① 背景(读回的目的)
    3 = 纯色层      → 10  只要源②，纯色层 REPLACE（不读背景）
    4 = TINT_ALPHA  → 11  源② base + 纯色层 tint + 源① 背景，走 alphaBlending
    5~7 = 未定义    → 00  不要源，宁可少画
```

`buf_free` 汇总：只认**本行选中的那几路**（没被选中的源在等自己的行任务，本来就 free）；
两路同时用时**两路都得能接下一行**。汇总放在合成器里，`CmdExec` 的接口就不会随源的个数变长。

### 5.2 掩码通路（ck 与 alpha 共用同一条路）

```
PaletteDecoder 查表输出 4 个像素（按像素对齐的 24 位组）
      ├─ colorKey（纯组合比较器）→ 每像素 3 位掩码（命中 = 000，否则 = 111）
      └─ 和颜色同拍往下走
              │  palette_data(12B) + palette_mask(12b)
              ▼
Compositor   选路 + 决定用不用掩码（alpha 的 α=0 掩码 与 ck 掩码【相与】）
              ▼
DDRPacker    96b→128b 字节兜，掩码兜 = 32 位（1 位 / 字节），【同一个 cnt_byte、同一个移位】
              ▼
WriteController  wr_strb = head_mask & tail_mask & ck_mask → AXI S3 → DDR3 的 DM
```

**三条必须记住的**：

1. **不能在 `Compositor` / 写侧按 24 位比颜色**。越往下游，手上越是"按字节流动、还要摆进 16 字节拍"的流，
   "24 位一组"不代表一个像素 ⇒ **按像素比颜色只能在源这一级做**（查表输出正好是按像素对齐的 24 位组）。
2. **掩码必须按【字节】，而且要跟数据走同一套移位**。3 字节 / 像素、16 字节 / 拍，3 不整除 16 ⇒ 一个像素横跨两拍；
   按字节给掩码，跨拍自动就对。`DDRPacker` 里**掩码兜必须是数据兜的逐位镜像**。
3. **`line_colorKey_en` = `flags[4]` & 本行取的是源②** ⇒ FILL 拿不到源，天然免疫
   （若做成全局开关，背景色正好是键色时整块一个字节都不写，屏上出现"刷不掉的鬼影"）。

### 5.3 alpha 混合级（`Compositor` 内的 `process/alphaBlending.v`）

```
out = bg + (fg − bg) × α / 255
      │     │          └── α：来自前景的调色板项（旁路 4 像素 × 8 位 = 32 位）
      │     └── fg：源②（PRAM 精灵）的 4 个像素
      └── bg：源①（DDR 读回的目的矩形）的 4 个像素
```

- **为什么用这个形式**：比 `fg×α + bg×(1−α)` **少一半乘法** —— 每通道只要 **1 个**乘法 ⇒ 4 像素 × 3 通道 = **12 个 DSP**（实测落进 DSP）；
- **÷255 不用除法器**：`q = (|fg−bg| × α + 1 + ((|fg−bg| × α) >> 8)) >> 8`，
  这是 `(x/255)` 在本设计乘积范围 `0 ≤ x ≤ 255×255` 上的**精确**算法 ⇒ **α = 255 时结果逐位等于 fg**
  （"开 α 且 α=255"与 REPLACE 完全一致），这条正好当自检判据；
- **α = 0 ⇒ 那 3 个字节的 WSTRB 关掉**（等价于 ck 效果）⇒ **复用 ck 那条掩码通路，不新增机制**；
- **α 走旁路**：`PaletteDecoder → Compositor` 一根 32 位线，**不进 96 位像素流** ⇒ 下游位宽一个字节不改。

**当前 RTL 的流水契约（2026-10-28）**：`Compositor` 先配对前景、背景、α 和 CK 掩码，再进入带 ready/valid 的四级 `alphaBlending`：差值/符号/绝对值 → DSP 乘法 → 精确 /255 → 加回背景。出口有四槽寄存队列，避免下游打包器的 ready 贯穿整条算术链。无反压时填满后每拍输出四个像素；停顿时数据和掩码保持配对。`pipeline_free` 必须同时确认四级与出口队列为空，才能参与下一行的 free 汇总。

`line_start` / `line_done` 在时钟沿清除流水尾部，优先于同沿输入；该沿可能已被上游取走的多余尾拍直接丢弃。完成信号不再组合门控 alpha / `PixelPipeline` 的入口 ready，出口 valid 仍在行边界屏蔽。此行为依赖写侧已收齐本行数据、下一行等待整链排空的契约。算术全组合旧 TB 已由握手版本替代；数值、持续吞吐、反压和 flush 由 `tb_alpha_pipeline` 覆盖，实测结论见 `实测数据.md`。

**α 为什么必须放调色板**（BRAM 账）：综合实测 **Memory Blocks 243 / 256**，只剩 13 块（其中素材 RAM 一项就 128 块）。

| 方案 | BRAM 增量 | 结论 |
|---|---|---|
| **α 放调色板**（256 项 24→32 位，4 个 lane） | **约 +2~4 块** | ✔ 可行 |
| α 放 PRAM 独立平面（8 位 / 像素） | 约 +114 块 | ✘ 放不下 |
| α 放 PRAM 独立平面（4 位 / 像素） | 约 +57 块 | ✘ 放不下 |

⇒ 语义上"α 是像素属性"没错，但物理上放不下第二个平面 ⇒ **一个索引 = 一种 (颜色, α)**。

**范围**：只支持 **PRAM 调色板精灵**（子弹 / 激光 / 光晕 / 爆炸）；**DDR 帧源的 alpha 不做**（那要 4 字节 / 像素的源格式）。
因为"背景 = 目的地址"，alpha 命令的 DDR 读**只有一路**（源② 是片上 PRAM 不占 AXI）⇒ 读口不需要分时仲裁。

```
PaletteRAM ─(4 索引/拍)─→ PaletteDecoder ─┬─→ RGB 96 位 ─┐
                                          └─→ α  32 位 ──┤
DDRSource(读目的矩形) ──────→ RGB 96 位 ──────────────────┼─→ Compositor ─→ DDRPacker ─→ WriteController ─→ DDR
                                                          │      (混合 12 DSP)   ↑ 行首 cnt_byte <= dst_off
填充色 FILL ─────────────────────────────────────────────┘
```

### 5.4 ★★ 两路源的取数门控（上板卡死过一次，别改回去）

alpha 是**第一次让两路源同时跑**，于是暴露了一条只跟"两路同时用"有关的规则：

| 事 | 规则 |
|---|---|
| 什么时候把源手上那一拍取走 | **以当前消费级的实际握手为准**。alpha 路径必须前景与背景同时有效、配对暂存可接收，才同时 pop；已配对数据随后独立通过 alpha 流水。单路旁路按其出口握手取数 |
| 本行写完之后 | `line_done` 之后的都是写侧不要的**尾巴** ⇒ **两路各取各的丢掉**，好让 `line_src_free` 拉高（DDR 源比 PRAM 源多几拍） |

不能继续套用早期“源 pop 永远等于最终 `pixel_valid & pixel_ready`”的组合式连线：现在源、配对暂存、alpha 和打包器之间存在多个弹性级，每一级分别按自己的 ready/valid 交接。尾部丢弃仍由本行完成后的 drain 负责。

**踩的坑**：`Compositor` 原本用 `src_rd_en = src_en & pixel_ready`（只看"下游想不想收"）。
**PRAM 源 2 拍就到，DDR 背景还在等 AXI 读回来** ⇒ 中间那几拍被逐个【取走并丢弃】⇒ 打包器什么都没收到 ⇒
写侧永远等 ⇒ `line_buffer_free` 不拉高 ⇒ `CmdExec` 发不出下一行 ⇒ **整条链卡死**（上板表现：黑屏 + 卡在 `exclusive_begin`）。
单路源时 `pixel_ready` 恰好等价于"确实收下"，所以两条老路一直没暴露。

> ★ **教训**：**"多路同时用"是新契约**。以后再加源（比如累积 RAM、第二层精灵），先问两件事：
> ① 我取走的条件跟下游收下的条件是不是同一个？② 我多出来的那一拍谁负责丢掉？

### 5.5 图片合成（2026-10 实现：两条命令三条 CI → 两张 PRAM 素材图合成一张）

**一句话**：一条命令画【几张图】就发几条参数 CI；每张图一格"行任务"广播下去，
两张 PRAM 素材图各读一趟，在 \`process/imageCombine.v\` 里合一张，再按最后一格那步的模式
去和背景 AB / 打包写回。

**命令形状（N = 图数，合成就是 2）**

| | 第 1 条（命令开始） | 第 2 条起（★ 一条 CI = 一张图） |
|---|---|---|
| \`funct3\` | \`1\`=FILL / \`2\`=BLIT | \`7\`=ARGS |
| \`inputs_0\` | \`{ 宽[31:16], 高[15:0] }\` | 这张图的源地址（纯色图填 0） |
| \`inputs_1\` | 目的地址 | \`{ more[31], flags[30:24], 这张图的参数[23:0] }\` |

- 第 1 条给几张图**共用**的（多大、画到哪）；第 2 条起每条给**一张图**。
- \`more=1\` 后面还有一张，\`more=0\` 这条是最后一张（结束词）。

**行任务口也按图并排**（和命令侧一个形状，加图不用改接口）

\`\`\`
line_start / line_dst_addr / line_w      ← 几张图共用
line_src_addr [32*N]  line_flags [8*N]  line_param [24*N]   ← 每张图一格
line_fx_en                               ← 本命令有没有第二张图（合成）；0 = 走老路
\`\`\`

- "看**最后一格**"的三根（\`line_*_last\`）：背景（DDR 源）、合成器、写侧看的都是
  **最终结果那一步**的模式 —— 合成时就是第 2 张图那格；单图命令第 2 格是空的，用 \`fx_en\` 选。
  ★ 这三根由 \`CmdExec\` 从上面三根宽线里**选好再广播**（广播归它所有）；
  顶层 \`GPU_2D\` 只把它们连过去，**不摆逻辑**。
- \`CmdExec\` **每行只发一次**行任务；**每张图各一份行地址递推**（各自跨距、各自 MX/MY 起点）。

**素材源（\`PaletteSource\`）内部两趟**

同一个 PRAM、同一个读口 ⇒ 两行只能串行读：

\`\`\`
第 1 趟：读第 1 格那张图那一行 → 流出去
切换  ：排空后发一拍 line_image_next（"后面来的都是图二"）
第 2 趟：读第 2 格那张图那一行 → 流出去
\`\`\`

- "图一这一行读完了"由**素材源自己数** \`needed_bytes\` 得出（边界由它划，下游不重复数）。
- 单图命令（\`line_fx_en=0\`）只有第 1 趟，**行为与老版本一位不差**。
- ★ 给 \`PaletteDecoder\` 的模式位必须**组合按趟选**（\`pass_r ? 第2格 : 第1格\`）：
  晚一拍 Decoder 就采到旧值，MX 的字内反序当场就错（m3palette 镜像用例立刻报错，踩过）。
- ★★ 选趟**不能只看 `pass_r`**：`pass_r` 是"收下行任务"那一拍才更新的，而 `line_start` 那一拍
  Decoder 就把它锁进 `mx_r` 了 —— 那一拍 `pass_r` 还是**上一条命令**留下的值（上一条是两张图就是 1）
  ⇒ 选到"第 2 格"（往往是全 0 的空格）⇒ **MX 命令的第一行不做字内反序**
  （症状：翻面后顶行 4 个像素错位、第 2 行起全对；2026-10 端到端仿真抓到）。
  现在只在 `pass_r & (state != S_IDLE)` 时才选第 2 格。

**\`imageCombine\` 就干两件事**（缓存第一张图那一行 + 合成），三态：

| 状态 | 干什么 | \`line_imgRow_free\` |
|---|---|---|
| \`S_EMPTY\` | 缓冲空（等 \`line_start\` / 这一行已合完） | 1 |
| \`S_FILL\` | 把图一那一行写进片上行缓冲（这一段 \`out_valid\` 恒 0） | 0 |
| \`S_COMBINE\` | 图二每来一拍，就从缓冲取一拍合一下出流 | 0 |

- 旁路：\`line_fx_en=0\` 时入口直通出口（data/mask/α 原样过），缓冲一个字节都不碰 ⇒ 单图/FILL 时序不变。
- **合成规则 = 按"上面那张（图二）的掩码"逐字节选**（★ 板上定稿）：图二这一字节要写 → 用图二；
  被 ck 抠掉（掩码 0）→ 用缓冲里图一的那一字节。
  `out_mask = 图二mask | 图一mask`；α 跟着"这个像素最终取了谁"（判据用该像素第一个字节的掩码）。
- **ck 判在合成【之前】，开关是命令级的**：`PaletteDecoder` 恒定按像素比键色（答"这张图哪几个
  字节透明"）；"这次要不要抠"由 `imageCombine` 按**命令级使能**（最后一格的 `flags[4]`，和写侧、
  背景看的是同一格）**一处** gate —— 不开就把两张图的掩码都当全 1 ⇒ 上面那张整张盖住下面那张。
  ★ 使能只有这一份：不用每张图各存一份开关，也不用让下游再判一次。
  ⇒ ③（两张都不开 ck）上面那张全赢：图二的 1 把图一的 0 盖住；
    ④（两张都开 ck）图二的白不写、图一的白也不写 ⇒ 被盖住的图一露出来 / 两张都白处落**底色**。
  ★ 试过"ck 挪到合成之后统一判"：那样图一整个看不见、④ 只剩一张图，板上验证后已改回。
- 行缓冲一拍一条（data+mask+α 一起存）：480 拍 × 140 位 ≈ 67 Kb ≈ **7 块 RAM10**。
- ★ 缓冲读是**预取**：处理第 n 拍的同一拍就把第 n+1 拍的读发出去（读是同步的，晚一拍就不够用）。

**AB 在哪**：还是 \`Compositor\` 里的 \`alphaBlending\` —— 前景 = 合成结果，背景 = DDR
读回的目的那一行，**那一级一行都没改**。

**接线**（\`GPU_2D\`）：\`PaletteSource → imageCombine → Factory(src1)\`；
\`src1_free = pal_src_free & combine_free\`（素材源能接 + 合成级缓冲空）；
\`DDRSource → Factory(src0)\` 不变。

### 5.6 颜色合成（第 2 层 = 纯色）：染色 / 加光 / 调色

**和 §5.5 的关系**：第 1 层、命令形状（3 条 CI）、`line_fx_en`、源② 内部两趟**全都不变** ——
只把第 2 层的"当前流"从素材换成一拍常量色：

```
上层 = 特效图（模式 A：每像素自己的 ARGB）              ← §5.5 图片合成
上层 = {4{C}}（模式 B：一拍常量色，浓度 = strength）    ← 本节 颜色合成
```

**各档效果落在哪一级**（★ 2026-10 定稿：**都在 `imageCombine` 逐字节那一级**，
`Compositor` 只负责"把上层造出来"—— 一拍常量色 + 浓度，`alphaBlending` 一行都没改）：

| 档 | 式子（`p` = 缓冲里那张图那个字节，`C` = 纯色层那个字节，`k` = 浓度） | 像什么 |
|---|---|---|
| 插值染色（`tint=1`） | `p ± floor(\|C − p\|·k/256)`（往 C 偏） | 受击闪红 / 冰冻变蓝 |
| 加光（`tint=2`） | `min(p + floor(C·k/256), 255)`（★ 饱和） | 发光 / 过曝 |
| 乘系数（`tint=3`） | `floor(p·k/256)` | 整体变暗 / 变亮 |
| 正片叠底（`tint=4`） | `floor(p·C/256)` | 影子 / 暗角 / 染色 |

**★ 为什么放在 `imageCombine` 而不是 `alphaBlending`**：AB 的两端是"合成结果 ↔ 目的里原有的背景"，
在那里染色会把**背景**也染上；而 tint 要的是"只作用在这张图上"。放在合成级，作用对象是
**缓冲里那张图（下层）的字节**，背景（读回来的目的像素）一根汗毛都动不到。
另外 REPLACE 模式压根不走 AB，放在 AB 里那种命令就没有 tint 可用。

**★ 只花了一个乘法器（一拍 12 个字节 = 12 个 DSP）**：四个式子的"被乘数 / 乘数"按模式 mux 好再乘一次 ——
`插值 = |C−p|·k`、`加光 = C·k`、`乘系数 = p·k`、`正片叠底 = p·C`。
四个式子各写一个乘法器要 `4×12 = 48` 个 DSP（综合报告实测：`imageCombine` 一个人吃 48 个），
mux 之后降到 12 个 —— **实测整机 DSP 从 68 回到 32**（见 `实测数据.md`）。
★ 乘积必须先落到 16 位再取高位：Verilog 里移位**不**把上下文宽度传给左操作数，
写成 `(a*b)>>8` 会先把乘积截成 8 位。

当前合成级先配对两层像素，再将绝对差/模式选择后的两个乘法操作数与掩码、α 一起寄存，下一拍执行共享 DSP 乘法，最后做加减/饱和/选色。三个弹性级都参与 `line_imgRow_free`；增加的拍延迟由 ready/valid 吸收，持续吞吐仍是一拍四像素。tint 保留原有乘积高 8 位的舍入；上表已修正文档原先误写的 `/255`，alpha 混合仍采用 §5.3 的精确 `/255`，此次没有改变任一算术结果。

- ★ `tint=0`（默认）⇒ 像素值回到 §5.5 的普通图片合成；合成流水的输出拍延迟通过握手传递。
- ★ **tint 只走纯色层这一条路**：`MODE=3` 是纯色层 **REPLACE**（不读背景，α 不进 AB）；
  `MODE=4`（TINT_ALPHA）是 **纯色层 tint + `alphaBlending`**：`src_en_of(4)=2'b11`，
  `fx_solid_en` 对 `MODE=3/4` 都打开，`imageCombine` / `alphaBlending` 一行不改，
  `imgCombine_alpha` 用 base 的 α（0/128/255 都保留）。
  C 侧对应 `CI_gpu2d_spriteAlphaTint()` / `spriteAlphaTintRect()`（3 条 CI：base + tint）。
  底图的 ROT90 在第 1 格、tint 的 tone 在第 2 格，两者不再抢 `param[23]`。
- ★ **不要改 `MODE=3` 的 `src_en_of` 去启用 AB**：mode 3 还被 CK 精灵共用，改成 `2'b11`
  会让每个 CK 精灵多读回一次目的行，帧内写不完（2026-10-20 踩过）。要 tint+AB 用 mode 4。
- ★ 参数从行任务**最后一格**的 `line_param` 来，在 `line_start` 那拍和 `flags_r` / `color_r` 一起锁存。
- ★ 镜像（MX/MY）按**每一格自己的 flags** 走：想让"底图"跟着朝向翻面，就把它写在**底图那一格**上
  （纯色层没有形状，那一格写了也没用）。带 MX 的底图 = `CmdExec` 算行尾字 + 取出器倒读那条老路，
  单图精灵怎么翻、它就怎么翻（`tb_m2loopback` 第九段就是照 demo 的"撞墙闪红"一条命令建的）。
- ★ 纯色层不读素材 ⇒ `PaletteSource` 只跑第 1 趟；`imageCombine` 直接进 `S_COMBINE`。
- ★★ 纯色层自己**不带掩码**（`solid_beat` 的掩码位恒 0）：它只给"往哪个颜色偏 + 浓度"。
  出口掩码 = **下层那张图的 ck 掩码** ⇒ 精灵外面不会被染出一个方块。
- ★★ 所以命令级 ck 位（`flags[4]`，取**最后一格**）在这个命令里**必须开着** ——
  不开的话掩码恒 1，整块矩形（连精灵四周）都会被染上色。`CI_gpu2d_combineTint()` 自动带这一位。
- ★ 纯色层那一格带下来的**是颜色、不是地址** ⇒ `CmdExec` 对它**不做行递推**（递推了第 2 行起颜色就变）。
- ★ 第 2 趟不发 ≠ 不发 `line_image_next`：那一拍照发（合成级靠它进 `S_COMBINE`），
  只是 `PaletteSource` 自己不读、直接回 `S_IDLE`。

**踩过的两个坑（2026-10，都在仿真里抓到的；症状都是"整块卡住"）**：

1. 把 `S_FILL` 那一趟也一起 gate 掉（"纯色层就不取源"）⇒ 图一卡死在第一拍：`source_valid` 一直有效、
   上游永远不被取走，同一个 beat 被反复写进缓冲、`wr_ptr` 涨到回绕也等不到 `line_image_next`
   ⇒ 这一行永远完不成。**纯色层要挡的只有 `S_COMBINE` 那一趟。**
2. 纯色层在 `S_FILL` 就顶替了 `cur_beat` ⇒ 缓冲里存的全是"纯色 + 掩码 0" ⇒ 出口掩码恒 0：
   行照样 `line_done`、屏幕上一个字节都不变。**替换只能发生在 `S_COMBINE`。**

## 6. 颜色键控（ck）

**一句话**：画精灵时**等于键色（默认白）的像素根本不写**，那块像素保持帧缓存里原有的内容（背景 + 其它元素）
⇒ 精灵外面不再有白框，也不用"先擦背景再压精灵"。

| 位 | 含义 |
|---|---|
| `flags[2:0]` | 合成模式（FILL / REPLACE / ALPHA） |
| `flags[3]` | 源类型：0 = DDR RGB888，1 = 片上 PRAM 调色板素材 |
| **`flags[4]`** | **颜色键控使能**（★ 逐命令，不是全局开关） |

C 侧：`CI_gpu2d_spriteCK()` / `CI_gpu2d_spriteRectCK()`（= 老的 sprite + `GPU2D_MODE_CKEY_EN`）。
老函数原样保留、不带这一位 ⇒ 行为和改造前一位不差（回归用）。
